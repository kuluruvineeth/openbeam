# Troubleshooting

## Authentication Errors

**Invalid API key or Application key:** Verify both keys are correct and have not been revoked. Re-generate from Datadog Organization Settings if needed. Both the API Key and Application Key are required.

**403 Forbidden:** The Application key lacks sufficient permissions. Ensure the associated user has at least read access to monitors, dashboards, incidents, services, notebooks, and SLOs.

**Wrong site:** If you get connection errors, verify your site setting matches your Datadog instance. Check your Datadog URL to determine the correct site (us1, us3, us5, eu, ap1, gov).

## Rate Limiting

**429 Too Many Requests:** The connector automatically backs off when rate limited. Datadog allows approximately 300 requests per minute. If syncs are consistently slow, consider disabling entity types you do not need or increasing the sync interval.

## Missing Data

**Dashboards without widget detail:** If individual dashboard detail fetches fail (rate limit or permission), the dashboard is still indexed with its title and description, but without widget content.

**Incidents not appearing:** The incidents API requires the Incident Management feature to be enabled in your Datadog account. Verify it is active.

**Service catalog empty:** The Service Catalog feature requires v2 service definitions to be configured. If your organization uses only APM service detection without explicit service definitions, the catalog may be empty.

## Sync Failures

**Incremental sync falling back to full:** This happens when the cursor state is stale or the API returns errors. The connector automatically recovers by running a full sync.

**Connection timeout:** Datadog API may be temporarily unavailable. The connector retries with exponential backoff up to 3 times for server errors.

**GOV site restrictions:** The Datadog Government site (ddog-gov.com) may have additional network restrictions. Ensure your OpenBeam deployment can reach the GOV API endpoint.
