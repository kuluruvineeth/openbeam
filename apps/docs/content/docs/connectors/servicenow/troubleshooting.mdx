# Troubleshooting

## OAuth Errors

| Error | Fix |
|-------|-----|
| `invalid_client` | Client ID does not match — verify in Application Registry |
| `invalid_secret` | Client Secret is wrong — regenerate in the application record |
| `redirect_uri_mismatch` | Redirect URL must match exactly in the application record |
| `invalid_grant` | Refresh token expired — reconnect OAuth flow |
| `access_denied` | User denied authorization or lacks required roles |

## Access Issues

| Issue | Fix |
|-------|-----|
| No records syncing | Verify the authenticating user has `itil` role for incidents |
| Knowledge articles missing | Enable `sync_knowledge` and verify the user has `knowledge` role |
| Change requests empty | Enable `sync_changes` in settings |
| Records partially missing | Check ACL rules — the user may lack access to certain categories |

## Sync Issues

| Issue | Fix |
|-------|-----|
| API throttling | Instance under load — reduce sync frequency or sync during off-peak hours |
| Table API timeout | Large tables may timeout — OpenBeam retries with smaller page sizes |
| Deleted records still in results | Records are detected as missing during full sync — trigger a full resync |
| Stale data | Verify incremental sync is running; check `sys_updated_on` field accuracy |

## Connection Issues

| Issue | Fix |
|-------|-----|
| Cannot connect | Verify instance name, Client ID, and Client Secret |
| Wrong instance | The instance is the part before `.service-now.com` in your URL |
| OAuth not enabled | Enable OAuth in System OAuth > Application Registry |
| Instance hibernating | Developer instances hibernate after inactivity — wake the instance first |
| API errors | Check [ServiceNow Status](https://status.servicenow.com/) |

<Callout type="info">
ServiceNow developer instances hibernate after 10 days of inactivity. If you see connection timeouts, log in to your instance first to wake it up.
</Callout>

## Debug Commands

```bash
curl https://api.your-domain.com/webhooks/servicenow/health

tail -f logs/worker.log | grep -i servicenow
```

## Error Reference

| Error | Code | Fix |
|-------|------|-----|
| `User Not Authenticated` | 401 | Reconnect OAuth — token expired |
| `Insufficient rights` | 403 | User lacks required role — add `itil` or `knowledge` role |
| `Record not found` | 404 | Record deleted or ACL restricted |
| `Too Many Requests` | 429 | Instance throttling — reduce request rate |
| `Internal Server Error` | 500 | ServiceNow-side issue — retry later |

## Common Patterns

### Issue: "No records appearing in search"

1. Check connector status is Active
2. Verify the authenticating user has `itil` role
3. Confirm which tables are enabled in configuration
4. Check ACL rules for the connecting user
5. Try manual Full Resync

### Issue: "Slow initial sync"

Large ServiceNow instances take time. Progress shown in connector status.
- 10,000 records: ~5 minutes
- 100,000 records: ~30 minutes
- 1,000,000+ records: Several hours

### Issue: "OAuth token keeps expiring"

1. Check the token lifetime in System OAuth settings
2. Increase the refresh token lifetime if it is too short
3. Verify the OAuth application is still active
4. OpenBeam automatically refreshes tokens — check logs for refresh errors

Still stuck? [Open an issue](https://github.com/kuluruvineeth/openbeam/issues) with error messages and logs.
