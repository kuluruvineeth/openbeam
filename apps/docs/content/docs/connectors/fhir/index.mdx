# FHIR Healthcare

Index de-identified clinical data from FHIR-compliant healthcare systems (Epic, Cerner, HAPI FHIR, Medplum) with mandatory PHI de-identification and HIPAA-compliant data pipelines.

## What Gets Indexed

All data is de-identified using the Safe Harbor method before indexing.

| Entity | Description |
|--------|-------------|
| Observations | Vital signs, lab results, clinical measurements |
| Encounters | Visit type, date, status, service provider |
| Conditions | Diagnosis code, clinical status, verification |
| Procedures | Procedure code, status, performed date |
| Devices | Device type, manufacturer, status, location |
| Device Metrics | Calibration data, measurement readings |
| Diagnostic Reports | Report type, status, results, conclusion |
| Document References | Document type, content, authoring date |
| Medications | Medication code, dosage, route |
| Patients | De-identified demographic data |

## Authentication

FHIR uses **SMART on FHIR backend services** authentication (JWT-based). The connector signs a JWT assertion with a private key and exchanges it for an access token at the FHIR server's token endpoint.

Required credentials:
- **Client ID** from your SMART on FHIR application registration
- **RSA/EC Private Key (PEM)** for JWT signing

## Sync

| Mode | Supported |
|------|-----------|
| Full sync | Yes (via Bulk Data Export) |
| Incremental sync | Yes (via R5 Subscriptions or `_lastUpdated` filter) |
| Real-time | No |

Full sync uses the FHIR Bulk Data Export (`$export`) operation for efficient retrieval of large datasets. Incremental sync uses R5 topic-based Subscriptions when available, falling back to `_lastUpdated` query filters.

## PHI De-identification

De-identification is **mandatory** and enabled by default. The connector implements the Safe Harbor method, removing all 18 HIPAA identifier categories:

- Names, dates (except year), addresses, phone numbers, email addresses
- Social Security numbers, medical record numbers, health plan beneficiary numbers
- Account numbers, certificate/license numbers, vehicle identifiers
- Device identifiers, URLs, IP addresses, biometric identifiers
- Full-face photographs, any other unique identifying number

Consent-aware search filtering uses FHIR Consent resources to restrict access based on patient consent status.

## Setup

1. Register a **SMART on FHIR backend services** application with your FHIR server
2. Generate an RSA or EC key pair for JWT signing
3. In OpenPlane, add the FHIR connector
4. Enter the FHIR server URL, FHIR version (R4 or R5), Client ID, and private key
5. Optionally configure which resource types to sync
6. Start the initial sync

### Settings

| Setting | Default | Description |
|---------|---------|-------------|
| FHIR Server URL | — | Base URL of the FHIR server (required) |
| FHIR Version | R4 | R4 (4.0.1) or R5 (5.0.0) |
| Client ID | — | SMART on FHIR application client ID (required) |
| Private Key (PEM) | — | RSA/EC private key for JWT signing (required) |
| PHI De-identification | On | Safe Harbor de-identification (required for HIPAA) |
| Resource Types | Patient, Observation, Device, Encounter, Condition | FHIR resource types to sync |
