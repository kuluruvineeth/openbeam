# Node-RED

Index flow definitions, node configurations, subflows, and automation logic from Node-RED instances via the Admin API. The connector makes your IoT integration logic searchable so you can find how data moves between systems.

Node-RED is a flow-based programming tool for wiring IoT devices, APIs, and online services. This connector indexes the automation logic itself -- not the data flowing through it.

## Authentication

**Method:** Admin API Access Token

Generate an access token in your Node-RED instance's security configuration or settings file.

[Node-RED Admin API docs](https://nodered.org/docs/api/admin/)

## Data Streams

| Stream | Description | Sync Mode | Interval |
|--------|-------------|-----------|----------|
| **Flows** | Flow definitions with node configurations, connections, and subflow references | Periodic | 5 min |
| **Settings** | Runtime version, installed palette modules, configuration | Periodic | 60 min |

Both streams support full backfill.

## Setup

1. Ensure your **Node-RED instance** has the Admin API enabled
2. Generate or retrieve an access token from the Node-RED security settings
3. In OpenBeam, add the Node-RED connector
4. Enter the Node-RED base URL and access token
5. Start the initial sync

## Configuration

| Setting | Default | Description |
|---------|---------|-------------|
| Node-RED URL | -- | Base URL of your Node-RED instance (required) |
| Access Token | -- | Admin API access token (required) |

## Sync Details

**Full sync** fetches all flow definitions from the Node-RED Admin API. Each flow is decomposed into its constituent nodes, and the topology (wiring between nodes) is preserved as searchable metadata.

**Incremental sync** uses flow revision tracking to detect changes since the last sync. Only flows with new revisions are re-indexed.

**Flow documents** include the flow name, node types present (e.g., `mqtt in`, `http request`, `function`), connection topology, and any subflow references. This lets you search for flows by the protocols or services they connect.

**Node configuration** documents capture individual node settings like MQTT broker addresses, HTTP endpoints, and function code. Sensitive credentials are excluded.

**Subflows** are indexed as reusable flow components with their input/output definitions and internal node structure.
