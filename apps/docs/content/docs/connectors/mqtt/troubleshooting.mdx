# Troubleshooting

## Connection Issues

<Accordions>
  <Accordion title="Connection refused">
    The connector cannot establish a TCP connection to the broker.

    **Causes:**
    - Broker is not running or not listening on the specified port
    - Firewall blocking the connection (port 1883/8883)
    - Wrong hostname or IP address
    - Broker bound to `localhost` only, not accepting remote connections

    **Fix:**
    1. Verify the broker is running: `mosquitto_sub -h broker-host -p 1883 -t '#' -C 1`
    2. Check firewall rules allow inbound traffic on the broker port
    3. For Mosquitto, verify `listener` is set to `0.0.0.0` (not `127.0.0.1`) in `mosquitto.conf`
    4. Test connectivity: `nc -zv broker-host 1883`
  </Accordion>

  <Accordion title="Authentication failed (CONNACK 5 / Not Authorized)">
    The broker rejected the provided credentials.

    **Fix:**
    1. Verify username and password are correct
    2. Check the broker's ACL configuration -- the user may exist but lack permissions for the requested topics
    3. For Mosquitto, verify `password_file` is configured and the user is listed
    4. Some brokers (EMQX, HiveMQ) have separate authentication backends (LDAP, database) -- check those configurations
  </Accordion>

  <Accordion title="Connection drops after a few seconds">
    Two clients using the same Client ID causes the broker to disconnect one.

    **Fix:**
    - OpenPlane generates a unique Client ID per connector instance. If you see disconnection loops, check that no other client is using the same ID
    - Increase the broker's `keepalive` interval if the connector is behind a NAT with aggressive timeout
  </Accordion>
</Accordions>

## TLS Errors

<Accordions>
  <Accordion title="Certificate validation failed">
    The broker's TLS certificate cannot be verified against the system CA bundle.

    **Fix:**
    1. If using a self-signed certificate, upload the CA certificate in the connector settings
    2. Verify the certificate's Common Name or SAN matches the hostname you are connecting to
    3. Check the certificate has not expired: `openssl s_client -connect broker:8883 -brief`
  </Accordion>

  <Accordion title="mTLS handshake failure">
    The broker rejected the client certificate or the key does not match.

    **Fix:**
    1. Verify the client certificate is signed by a CA the broker trusts
    2. Confirm the client key matches the certificate: `openssl x509 -noout -modulus -in client.crt | md5` should match `openssl rsa -noout -modulus -in client.key | md5`
    3. Check the broker's `require_certificate true` and `cafile` settings point to the correct CA
  </Accordion>

  <Accordion title="Protocol error on port 1883 with mqtts://  ">
    Using `mqtts://` (TLS) against a non-TLS port, or `mqtt://` against a TLS port.

    **Fix:**
    - Use `mqtt://` with port 1883 (plain TCP)
    - Use `mqtts://` with port 8883 (TLS)
    - Do not mix protocols and ports
  </Accordion>
</Accordions>

## No Messages Appearing

<Accordions>
  <Accordion title="Wrong topic pattern">
    The subscription pattern does not match any topics the devices publish to.

    **Fix:**
    1. Subscribe to `#` temporarily to see all traffic: `mosquitto_sub -h broker -t '#' -v`
    2. Compare actual topic paths with your configured patterns
    3. MQTT wildcards are case-sensitive -- `Plant/+/Sensors/#` does not match `plant/+/sensors/#`
  </Accordion>

  <Accordion title="QoS mismatch">
    The connector subscribes at QoS 1 by default. If the broker downgrades to QoS 0, messages may be lost during brief disconnections.

    **Fix:**
    - Verify the broker supports QoS 1 for the subscribed topics
    - Check broker ACLs -- some configurations restrict QoS levels per topic
  </Accordion>

  <Accordion title="Retained messages not indexed">
    Retained messages are delivered once on subscription. If the connector was restarted, it receives retained messages again but deduplicates them.

    **Fix:**
    - This is expected behavior. Retained messages appear as the latest value for each topic
    - To force re-indexing of retained messages, disconnect and reconnect the connector
  </Accordion>
</Accordions>

## Sparkplug B Issues

<Accordions>
  <Accordion title="Malformed Sparkplug B payloads">
    The connector expects standard Sparkplug B protobuf encoding. Custom or modified payloads fail to decode.

    **Fix:**
    1. Verify devices publish compliant Sparkplug B payloads using the [Sparkplug B specification](https://sparkplug.eclipse.org/)
    2. Check the topic namespace follows `spBv1.0/{group_id}/{message_type}/{edge_node_id}/{device_id}`
    3. Use a Sparkplug-aware MQTT client to validate payloads before connecting to OpenPlane
  </Accordion>

  <Accordion title="Missing DBIRTH/NBIRTH messages">
    Device and node birth certificates define the metric schema. Without them, DDATA/NDATA metrics lack context.

    **Fix:**
    - Ensure edge nodes publish NBIRTH on connection and DBIRTH for each device
    - Subscribe to `spBv1.0/+/NBIRTH/#` and `spBv1.0/+/DBIRTH/#` in addition to DDATA/NDATA topics
    - If births were missed, restart the edge node to trigger re-publication
  </Accordion>
</Accordions>

## Aggregation Issues

<Accordions>
  <Accordion title="Messages arriving too fast -- high memory usage">
    High-frequency sensors (>100 msg/s per topic) can cause large aggregation buffers.

    **Fix:**
    - Increase the aggregation window from 60s to 300s to reduce document throughput
    - Use more specific topic patterns to limit the number of subscribed topics
    - Consider pre-aggregating at the edge (e.g., in Node-RED) before MQTT publication
  </Accordion>

  <Accordion title="Aggregation window too large -- stale data">
    With a large aggregation window, sensor values appear delayed in search results.

    **Fix:**
    - Reduce the aggregation window to 30s or 15s for near-real-time visibility
    - Set aggregation to 0 to disable windowing entirely (one document per message)

    <Callout type="warn">
      Disabling aggregation on high-frequency topics generates a large volume of documents. Only disable for low-frequency topics (&lt;1 msg/min).
    </Callout>
  </Accordion>
</Accordions>

## Debug Checklist

```bash
# Test broker connectivity
nc -zv broker-host 1883

# Subscribe to all topics and observe traffic
mosquitto_sub -h broker-host -p 1883 -t '#' -v -u username -P password

# Test TLS connection
openssl s_client -connect broker-host:8883 -brief

# Check certificate expiry
openssl s_client -connect broker-host:8883 2>/dev/null | openssl x509 -noout -dates
```

Still stuck? [Open an issue](https://github.com/kuluruvineeth/openplane/issues) with the broker type, connection settings (redact credentials), and error messages.
