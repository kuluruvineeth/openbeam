## Workflows

| Workflow | Purpose |
|----------|---------|
| `missionOrchestratorWorkflow` | Top-level mission lifecycle, agent spawning, health monitoring |
| `missionAgentRunWorkflow` | Per-agent execution with tool access |
| `sharedAgentPoolWorkflow` | Shared agent resource management |
| `missionLinearRunWorkflow` | Sequential task execution |

## Mission Lifecycle

1. **DRAFT** — Mission created, objective defined
2. **ACTIVE** — Orchestrator workflow started, agents spawned
3. **Running** — Agents claim tasks, execute runs, produce artifacts
4. **Reflection** — Progress evaluation, re-planning if needed
5. **COMPLETED** / **CANCELLED** — Terminal states

## Agent Tools (Mission-Specific)

| Tool | Purpose |
|------|---------|
| `missionSpawnAgent` | Create new MissionAgent linked to BackgroundAgent |
| `missionSendMessage` | Inter-agent messaging via MissionComment |
| `missionEvaluateProgress` | Assess mission health and completion |
| `missionRequestReplan` | Signal orchestrator for task restructuring |
| `missionEscalate` | Escalate blocked tasks |
| `missionRequestPeerReview` | Request agent-to-agent code/work review |
| `missionStoreTeamKnowledge` | Persist learnings to TeamKnowledge |

## Budget Tracking

`Mission.budgetCents` / `consumedCents` — each `MissionRun` adds `costCents` to the running total. Orchestrator pauses when budget approaches limit.
