## Scaling Strategy by Layer

| Layer | Strategy | Trigger | Target |
|-------|----------|---------|--------|
| **web** | Horizontal pod scaling | CPU / request count | 2-10 instances |
| **server** | Horizontal pod scaling | CPU / connection count | 2-8 instances |
| **worker** | Task-queue-based scaling | Queue depth per task queue | 1-20 per queue |
| **engine (CPU)** | Request-based scaling | Queue depth | 2-8 instances |
| **engine (GPU)** | GPU utilization scaling | GPU memory / queue | 1-4 instances |

## Temporal Worker Scaling

7 task queues, each independently scalable:

| Task Queue | Concurrency | Activities | Scale Factor |
|------------|-------------|------------|--------------|
| `sync-queue` | High | fetchBatch, transform, index | Connector count |
| `canvas-queue` | Medium | executeCanvasNode, parallel | Active canvas runs |
| `mission-queue` | Medium | executeAgentStep, spawn | Active missions |
| `processing-queue` | High | parse, chunk, embed, NER | Document backlog |
| `scheduled-queue` | Low | cleanup, analytics, LTR | Fixed schedule |
| `webhook-queue` | Burst | processWebhookEvent | Webhook volume |
| `default-queue` | Low | Miscellaneous | Baseline |

## Database Scaling

### PostgreSQL
- **Primary**: All writes, real-time reads
- **Read replicas**: Analytics queries, search profile reads, audit log queries
- **Connection pooling**: PgBouncer (transaction mode)
- **Partitioning**: `AIUsageLog` by month, `SyncHistory` by month, `WorkflowAuditLog` by month

### Redis
- **Cache cluster**: User sessions, search results, rate limit counters
- **Pubsub instance**: Real-time UI updates, agent messaging
- **Lock instance**: Fence tokens, distributed locks (Redlock)

### Vespa
- **Content nodes**: Document sharding by `teamId` hash
- **Container nodes**: Query processing, re-ranking
- **Config server**: Schema deployment, node management
- **Scaling**: Add content nodes for document count, container nodes for query throughput

## CDN and Static Assets

| Asset Type | Cache Strategy | TTL |
