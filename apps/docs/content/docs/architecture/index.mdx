# Architecture

OpenPlane is a modular, TypeScript-first platform built as a Turborepo monorepo. It connects to 30+ data sources, syncs content through durable Temporal workflows, indexes everything in Vespa for hybrid search, and serves AI-powered answers grounded in your data.

## How it works (summary)

1. **Connect** -- OAuth or API key into Slack, Gmail, Notion, Linear, GitHub, MQTT, OPC-UA, and 30+ sources
2. **Sync** -- Temporal workflows fetch, transform, chunk, embed, and index documents into Vespa
3. **Search** -- Hybrid BM25 + semantic search with permission-aware filtering in under 200ms
4. **Answer** -- AI agents ground answers in your data with inline citations

## Package map

All shared logic lives in packages. Apps are thin adapters that compose packages.

```
apps/
├── web           → @openplane/api, @openplane/auth, @openplane/ui
├── server        → @openplane/api, @openplane/services, @openplane/ai, @openplane/temporal
├── worker        → @openplane/temporal, @openplane/services, @openplane/vespa, @openplane/ai
├── engine        → standalone Python service
├── cli           → standalone Go binary
└── daemon        → @openplane/types (protocol contracts)

packages/
├── types         ← SINGLE SOURCE OF TRUTH for all shared types
├── ai            → agents, tools, RAG pipeline, MCP
├── api           → tRPC routers (consumed by web + server)
├── auth          → authentication (better-auth)
├── db            → Prisma schema, typed queries
├── services      → connector business logic (one dir per connector)
├── temporal      → workflow definitions + activity implementations
├── vespa         → search client, schema, GenericDocument
├── redis         → cache client, rate limiting, locks
├── integrations  → OAuth configs, app definitions, logos
├── media         → video processing (TwelveLabs)
├── storage       → S3/R2 client
├── edge-core     → SQLite storage, sync protocol, task scheduler
├── edge-search   → FTS5 + vector hybrid search (offline)
└── edge-ai       → edge RAG, NER, query rewriting (offline)
```

## Dependency direction

Dependencies flow in one direction: apps import packages, packages import other packages, never the reverse.

```
apps/web ──────┐
apps/server ───┼──> packages/api ──> packages/services ──> packages/db
apps/worker ───┘         │                  │                  │
                         │                  │                  │
                         v                  v                  │
                  packages/temporal  packages/vespa            │
                         │                  │                  │
                         v                  │                  │
                  packages/redis            │                  │
                         │                  │                  │
                         └──────────┬───────┴──────────────────┘
                                    v
                           packages/types   ← SINGLE SOURCE OF TRUTH
```

Circular dependencies are bugs. Run `bun run check:circular` to detect them.

## Design principles

**Durable execution over fire-and-forget.** Every background job runs as a Temporal workflow with automatic retries, checkpointing, and visibility. No cron jobs, no Bull queues, no lost work.

**Permission-aware by default.** Search results are filtered against pre-computed permission tables synced from source systems. Users only see documents they have access to in the original tool.

**Connector isolation.** Each connector is a self-contained plugin in `packages/services/src/{name}/` with its own client, transformer, rate limiter, and tests. No cross-connector imports.

**Agent-native.** Every platform capability is exposed as a composable tool. Agents use the same APIs as the UI. New workflows emerge from prompts, not code.

**Edge-capable.** The edge runtime (`edge-core`, `edge-search`, `edge-ai`) provides offline search and AI on SQLite for air-gapped environments. Merkle-tree-based sync keeps edge nodes consistent with the cloud.
