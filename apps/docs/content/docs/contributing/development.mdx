# Development Guide

Everything you need to work on the OpenBeam codebase locally.

## Local Setup

### Install Bun

OpenBeam uses **Bun** exclusively as its package manager and runtime. Do not use npm, pnpm, or yarn.

```bash
curl -fsSL https://bun.sh/install | bash
```

Verify:

```bash
bun --version  # Should be 1.3.2+
```

### Install Dependencies

```bash
git clone https://github.com/kuluruvineeth/openbeam.git
cd openbeam
bun install
```

### Start Infrastructure

PostgreSQL, Redis, Vespa, and Temporal run in Docker:

```bash
docker compose -f scripts/deploy/infra-hetzner-compose.yaml up -d
```

### Configure Environment

```bash
cp .env.example .env
```

Edit `.env` with your local service URLs. The defaults work with the Docker Compose setup.

### Initialize Database

Push the Prisma schema to your local PostgreSQL:

```bash
bun run db:push
```

### Start Development

```bash
bun run dev
```

This starts all apps in parallel using Turborepo.

## Running Individual Apps

Run only the services you need:

| Command | What it starts | Port |
|---------|---------------|------|
| `bun run dev` | All apps in parallel | -- |
| `bun run dev:web` | Next.js frontend | 3001 |
| `bun run dev:server` | Hono API server | -- |
| `bun run dev:docs` | Documentation site | 4000 |

For individual apps not covered by root scripts:

```bash
cd apps/worker && bun run dev
cd apps/engine && python -m uvicorn main:app --reload
```

## Testing

Tests are mandatory for all non-trivial changes.

### Bun Tests

Most packages use `bun:test`:

```bash
bun test                       # Run all tests
bun test --watch               # Watch mode
bun test packages/services/    # Tests in a specific package
bun test path/to/file.test.ts  # Single file
```

Test files live in `__tests__/` directories adjacent to source files:

```text
packages/services/src/linear/
├── sync/
│   ├── full.ts
│   └── incremental.ts
└── __tests__/
    ├── sync.test.ts
    └── transformers.test.ts
```

### Temporal Tests (Node.js + vitest)

The Temporal SDK requires V8 APIs (`v8.promiseHooks.createHook`) that Bun does not support. Temporal tests use vitest with Node.js:

```bash
cd packages/temporal
bun run test              # Unit tests (vitest, 30s timeout)
bun run test:integration  # Integration tests (vitest, 120s timeout)
```

Unit tests mock activities. Integration tests spin up a real `TestWorkflowEnvironment` for end-to-end workflow execution.

### What to Test

| Change type | Required tests |
|-------------|---------------|
| New connector | Client, transformer, sync generator |
| API endpoint | Request/response validation |
| Temporal workflow | Workflow logic with mocked activities |
| Database query | Query correctness with test data |
| UI component | Rendering, user interaction |
| Algorithm | Edge cases, boundary conditions |

### Test Conventions

- Test file names: `*.test.ts` for unit tests, `*.integration.test.ts` for integration tests
- Use `describe` blocks to group related tests
- Test behavior, not implementation
- Mock external APIs at the HTTP boundary

## Linting and Formatting

OpenBeam uses **Biome** via Ultracite for linting and formatting:

```bash
bun run check
```

This runs Biome across the entire monorepo. Fix all issues before committing.

### Biome Rules

| Rule | What it means |
|------|--------------|
| No `++`/`--` | Use `+= 1` or `-= 1` instead |
| No unnecessary `async` | Remove `async` if the function body has no `await` |
| Literal keys preferred | `{ name: "x" }` not `{ "name": "x" }` |
| Max 4 params per function | Use an options object for more |
| No empty blocks | Use `const noop = Function.prototype as () => void` |
| No variable shadowing | Rename callback params that shadow outer variables |

### Import Conventions

- `.js` import specifiers in `.ts` files are valid for Node/Bun ESM targets (`apps/daemon`, `apps/server`, `apps/worker`)
- Never import `.ts`/`.tsx` directly in runtime code
- For Expo/Metro-facing code, use extensionless relative imports (`./foo`)

## Database

### Prisma Commands

| Command | Purpose |
|---------|---------|
| `bun run db:push` | Push schema to database (development) |
| `bun run db:studio` | Open Prisma Studio browser UI |
| `bun run db:migrate --name <name>` | Create a new migration |
| `bunx prisma migrate deploy` | Apply migrations (production) |
| `bunx prisma migrate resolve --applied <name>` | Resolve a migration |

### Database Access Pattern

All database operations go through `@openbeam/db` functions. Never use Prisma directly in services:

```typescript
// Correct: use db package functions
import { findConnectorById, updateConnector } from "@openbeam/db";

// Wrong: direct Prisma access
import prisma from "@openbeam/db";
await prisma.connector.update({ ... });
```

All db functions take `db: Database` as the first parameter:

```typescript
export const findConnectorById = async (
  db: Database,
  id: string
): Promise<Connector | null> =>
  db.connector.findUnique({ where: { id } });
```

## Building

Build all packages and apps:

```bash
bun run build
```

Type-check without emitting files:

```bash
bun x tsc --noEmit
```

Turborepo caches build outputs. Unchanged packages skip rebuilding.

## Package Dependency Rules

Packages follow a strict dependency hierarchy. Inner packages must not import from outer packages.

```text
apps/ (web, server, worker, daemon)
  └── packages/api
        ├── packages/services
        │     ├── packages/db
        │     ├── packages/vespa
        │     ├── packages/redis
        │     └── packages/storage
        ├── packages/ai
        ├── packages/temporal
        └── packages/auth
              └── packages/db

packages/types  ← imported by ALL packages (no deps of its own)
packages/integrations ← imported by services, server, web
```

Rules:
- `packages/types` has zero internal dependencies
- `packages/db` never imports from `packages/services`
- `packages/services` never imports from `apps/*`
- Import shared types from `@openbeam/types`, not from source packages

## CLI Development (Go)

The Go CLI lives in `apps/cli/` and uses Go 1.24 with Cobra:

```bash
cd apps/cli
go build -o openbeam ./cmd/openbeam   # Build
go test ./...                            # Test
golangci-lint run                        # Lint
goreleaser build --snapshot --clean      # Release build
```

CLI structure:

| Directory | Purpose |
|-----------|---------|
| `apps/cli/cmd/openbeam/` | Entry point |
| `apps/cli/internal/cmd/` | Command implementations |
| `apps/cli/internal/auth/` | Auth store |
| `apps/cli/internal/config/` | Config management |
| `apps/cli/internal/api/` | HTTP client |
| `apps/cli/internal/mcp/` | MCP server |
| `apps/cli/internal/plugin/` | Plugin system |

## Pre-Commit Checklist

Before every commit:

```bash
bun test              # Tests pass
bun x tsc --noEmit    # Types check
bun run check         # Lint clean
bun run build         # Build succeeds
```

## Troubleshooting

| Problem | Solution |
|---------|---------|
| `bun install` fails | Delete `node_modules` and `bun.lock`, re-run `bun install` |
| Database connection refused | Verify Docker is running: `docker compose -f scripts/deploy/infra-hetzner-compose.yaml ps` |
| Temporal tests fail with V8 error | Run with `bun run test` (uses vitest + Node.js), not `bun test` |
| Port 3001 in use | Kill the existing process: `lsof -ti:3001 \| xargs kill` |
| Type errors after `git pull` | Run `bun install` then `bun run build` to rebuild packages |
