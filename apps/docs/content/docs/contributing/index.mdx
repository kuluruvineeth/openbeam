# Contributing to OpenPlane

OpenPlane grows through community connectors. Every connector you build makes enterprise search better for thousands of teams.

Connectors are the highest-impact contribution you can make. Each one takes 2-3 hours and immediately unlocks a new data source for every OpenPlane user.

## Prerequisites

| Tool | Version | Install |
|------|---------|---------|
| **Bun** | 1.3.2+ | `curl -fsSL https://bun.sh/install \| bash` |
| **Node.js** | 20+ | Required for Temporal SDK tests |
| **Docker** | Latest | PostgreSQL, Redis, Vespa, Temporal |
| **Go** | 1.24+ | CLI development only |

## Quickstart

Three commands to a running dev environment:

```bash
git clone https://github.com/kuluruvineeth/openplane.git
cd openplane
bun install
```

Configure your local services:

```bash
cp .env.example .env
docker compose -f scripts/deploy/infra-hetzner-compose.yaml up -d
```

Push the database schema and start everything:

```bash
bun run db:push
bun run dev
```

The web app runs at `http://localhost:3001`.

## Monorepo Map

OpenPlane uses Turborepo with Bun workspaces. Everything is TypeScript except the CLI (Go) and the ML engine (Python).

### Apps

| App | Port | What it does |
|-----|------|-------------|
| `apps/web` | 3001 | Next.js frontend |
| `apps/server` | -- | Hono API server |
| `apps/worker` | -- | Temporal workflow workers |
| `apps/engine` | 8000/8001 | Python ML service (CPU/GPU) |
| `apps/daemon` | -- | Local headless daemon for agent orchestration |
| `apps/cli` | -- | Go CLI (`openplane` command) |
| `apps/docs` | 4000 | Documentation site |

### Packages

| Package | Purpose |
|---------|---------|
| `packages/types` | Shared type definitions -- single source of truth |
| `packages/ai` | AI SDK providers, agents, tools, RAG |
| `packages/api` | tRPC routers |
| `packages/auth` | Authentication logic |
| `packages/db` | Prisma schema and queries |
| `packages/integrations` | Connector configs, OAuth, logos |
| `packages/services` | Connector business logic (sync, transform) |
| `packages/temporal` | Temporal workflows and activities |
| `packages/vespa` | Vespa search client |
| `packages/redis` | Redis client, rate limiting, cache |
| `packages/storage` | S3/R2 storage |

## Commit Conventions

All commits follow `type(scope): subject` in imperative mood. One-line subjects, no body needed.

```text
feat(github): add discussion sync
fix(sync): handle rate limit retry after header
refactor(services): extract pagination helper
test(linear): add incremental sync edge cases
chore(deps): update temporal sdk to 1.11
docs(connectors): add FHIR setup guide
perf(vespa): batch embedding requests
```

| Type | When to use |
|------|-------------|
| `feat` | New feature or capability |
| `fix` | Bug fix |
| `refactor` | Code restructuring, no behavior change |
| `test` | Adding or updating tests |
| `chore` | Maintenance, dependency updates |
| `docs` | Documentation changes |
| `perf` | Performance improvement |

## Testing

Tests are mandatory for all non-trivial changes. Run the full suite before submitting a PR:

```bash
bun test              # All tests
bun test --watch      # Watch mode
bun test <file>       # Single file
```

Temporal SDK tests require Node.js and use vitest:

```bash
cd packages/temporal
bun run test              # Unit tests (vitest, 30s timeout)
bun run test:integration  # Integration tests (vitest, 120s timeout)
```

Test files live in `__tests__/` directories next to source files.

## Pre-Commit Checklist

Every PR must pass these checks:

```bash
bun test              # Tests pass
bun x tsc --noEmit    # Types check
bun run check         # Biome lint clean
bun run build         # Build succeeds
```

## Pull Request Process

1. Fork the repository and create a feature branch from `dev`
2. Make your changes with tests
3. Run the pre-commit checklist above
4. Open a PR against `dev` with a clear description
5. Address review feedback
