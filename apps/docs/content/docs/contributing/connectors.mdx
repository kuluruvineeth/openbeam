# Building a Connector

Every connector follows the same four-layer architecture. This guide walks you through each layer using the Linear connector as the reference implementation.

By the end, you will have a production-ready connector that syncs data from a third-party API into OpenBeam's search index.

## Architecture

A connector spans four packages. Each layer has a single responsibility:

| Layer | Package | What it does |
|-------|---------|-------------|
| **Types** | `packages/types/src/services/connectors/{name}.ts` | Zod schemas for sync cursors, transform contexts, API types |
| **Integration** | `packages/integrations/src/{name}/` | App definition, auth config, data streams, settings, logo |
| **Services** | `packages/services/src/{name}/` | API client, sync generators, entity transformers |
| **Temporal** | `packages/temporal/src/` | Wiring into the generic sync workflow |

```text
packages/types/src/services/connectors/linear.ts     <- Zod schemas
packages/integrations/src/linear/config.ts            <- App definition
packages/services/src/linear/                         <- Business logic
  ├── client.ts                                       <- API client
  ├── sync/full.ts                                    <- Full sync generator
  ├── sync/incremental.ts                             <- Delta sync generator
  └── transformers/issue.ts                           <- Entity -> GenericDocument
```

## Step 1: Define Types

All shared types live in `packages/types`. Define Zod schemas for your sync cursor, sync options, and transform context.

**File:** `packages/types/src/services/connectors/{name}.ts`

```typescript
import { z } from "zod";

// Sync cursor tracks progress across sync runs
export const ExampleSyncCursorSchema = z.object({
  lastSyncTime: z.number().optional(),
  pageToken: z.string().optional(),
});

export type ExampleSyncCursor = z.infer<typeof ExampleSyncCursorSchema>;

// Sync options configure sync behavior
export interface ExampleSyncOptions {
  cursor?: ExampleSyncCursor;
  batchSize?: number;
  forceFullSync?: boolean;
}

// Transform context provides connector metadata to transformers
export interface ExampleTransformContext {
  connectorId: string;
  connectorType: string;
  teamId: string;
  workspaceId: string;
}

// API entity types
export const ExampleEntitySchema = z.object({
  id: z.string(),
  title: z.string(),
  description: z.string().nullable(),
  createdAt: z.string(),
  updatedAt: z.string(),
  url: z.string(),
});

export type ExampleEntity = z.infer<typeof ExampleEntitySchema>;
```

Then add the sub-path export to `packages/types/package.json`:

```json
{
  "exports": {
    "./services/connectors/example": {
      "types": "./dist/services/connectors/example.d.ts",
      "default": "./src/services/connectors/example.ts"
    }
  }
}
```

<Callout type="info">
The types package is the single source of truth. Never define shared types in the services or integrations packages.
</Callout>

### Auth Types

| Auth Type | When to use | Config |
|-----------|------------|--------|
| `AuthType.OAUTH2` | SaaS apps (Linear, GitHub, Slack) | `authUrl`, `tokenUrl`, `scopes` |
| `AuthType.API_KEY` | API key/token services (Samsara, Matterport) | `headerName`, `documentationUrl` |
| `AuthType.SERVICE_ACCOUNT` | Service accounts (Google Workspace) | Service account config |

For OAuth connectors, also create `oauth.ts` with token exchange functions (`generateAuthUrl`, `exchangeCode`, `refreshToken`).

### Sync Modes

| Mode | Constant | Behavior |
|------|----------|----------|
| Real-time | `SyncMode.REALTIME` | Webhook-driven instant updates |
| Periodic | `SyncMode.PERIODIC` | Scheduled interval-based sync |
| On-demand | `SyncMode.ON_DEMAND` | Manual trigger only |

## Step 3: Service Implementation

The service package contains all business logic: API client, sync generators, and entity transformers.

### Directory Structure

```text
packages/services/src/{name}/
├── index.ts           # Public exports
├── auth.ts            # IntegrationAuth implementation
├── client.ts          # API client with rate limiting
├── types.ts           # Error classes (ConnectorApiError)
├── api/
│   ├── index.ts       # Barrel export
│   └── entities.ts    # API query functions
├── sync/
│   ├── index.ts       # Barrel export
│   ├── full.ts        # Full sync generator
│   ├── incremental.ts # Delta sync generator
│   └── utils.ts       # Batch helpers
├── transformers/
│   ├── index.ts       # Barrel export
│   └── entity.ts      # Entity → GenericDocument
└── push/              # Webhook handler (if supported)
    └── notification-handler.ts
```

### API Client

Wrap the third-party API with rate limiting and error handling. From the actual Linear client:

```typescript
// packages/services/src/linear/client.ts
import { type RateLimitConfig, rateLimiter } from "@openbeam/redis";
import type { LinearClientConfig } from "@openbeam/types/services/connectors/linear";

const DEFAULT_RATE_LIMITS: RateLimitConfig = {
  requestsPerMinute: 50,
  requestsPerHour: 1500,
  burstLimit: 20,
};

export function createLinearClient(config: LinearClientConfig): LinearClient {
  const { connectorId, accessToken, rateLimitConfig = DEFAULT_RATE_LIMITS } = config;

  async function checkRateLimit(): Promise<void> {
    const { allowed } = await rateLimiter.checkConnectorRateLimit(
      connectorId,
      "linear",
      rateLimitConfig as RateLimitConfig
    );
    if (!allowed) {
      const quotaAvailable = await rateLimiter.waitForQuota(
        connectorId, "linear", rateLimitConfig as RateLimitConfig, 5
      );
      if (!quotaAvailable) {
        throw new LinearApiError({
          message: "Rate limit exceeded",
          code: "RATELIMITED",
          retryable: true,
          retryAfter: 60,
        });
      }
    }
  }

  return {
    connectorId,
    query: executeGraphQL,
    mutation: executeGraphQL,
    getRateLimitState,
    healthCheck,
  };
}
```

### Full Sync Generator

The core sync pattern: an async generator that yields batches of `GenericDocument` objects. From the actual Linear full sync:

```typescript
// packages/services/src/linear/sync/full.ts
import type {
  LinearSyncBatch,
  LinearSyncCursor,
  LinearTransformContext,
} from "@openbeam/types/services/connectors/linear";
import type { GenericDocument } from "@openbeam/vespa";

export async function* fullSync(
  client: LinearClient,
  context: LinearTransformContext,
  options: FullSyncOptions = {}
): AsyncGenerator<LinearSyncBatch<GenericDocument>, void, undefined> {
  const { batchSize = 50, syncComments = true } = options;

  const userLookup = await createUserLookup(client);
  const enrichedContext = { ...context, userLookup };
  const cursor: LinearSyncCursor = { lastSyncTime: Date.now(), syncedTeams: [] };
  const state: SyncState = { documents: [], processed: 0, skipped: 0, errors: 0 };

  for await (const team of getAllTeams(client)) {
    cursor.syncedTeams?.push(team.id);

    for await (const issue of getAllTeamIssues(client, team.id)) {
      if (issue.archivedAt) {
        state.skipped += 1;
        continue;
      }

      const comments = syncComments
        ? await collectIssueComments(client, issue.id)
        : [];
      const document = await transformIssue(issue, enrichedContext, { comments });
      state.documents.push(document);
      state.processed += 1;

      if (state.documents.length >= batchSize) {
        yield createSyncBatch(state.documents, cursor, true, state);
        state.documents = [];
      }
    }
  }

  if (state.documents.length > 0) {
    yield createSyncBatch(state.documents, cursor, false, state);
  }
}
```

Key patterns:
- **Async generator** (`async function*`) enables streaming batches to the indexer
- **Cursor tracking** persists progress across sync runs
- **Batch yielding** controls memory usage -- yield every `batchSize` documents
- **Skip logic** filters archived or stale entities

### Incremental Sync

Uses timestamps or change tokens to fetch only modified data since the last sync:

```typescript
export async function* incrementalSync(
  client: ExampleClient,
  ctx: ExampleTransformContext,
  options: ExampleSyncOptions
): AsyncGenerator<SyncBatch> {
  const since = options.cursor?.lastSyncTime;
  const entities = await client.listEntities({ updatedSince: since });

  for (const entity of entities) {
    const document = transformEntity(entity, ctx);
    yield { items: [document], cursor: { lastSyncTime: Date.now() }, hasMore: false };
  }
}
```

### Transformer

Maps a third-party entity to OpenBeam's `GenericDocument` schema. From the actual Linear issue transformer:

```typescript
// packages/services/src/linear/transformers/issue.ts
import type { LinearIssue, LinearTransformContext } from "@openbeam/types/services/connectors/linear";
import type { GenericDocument } from "@openbeam/vespa";

export async function transformIssue(
  issue: LinearIssue,
  context: LinearTransformContext,
  options: IssueTransformOptions = {}
): Promise<GenericDocument> {
  const title = `${issue.identifier}: ${issue.title}`;
  const content = buildIssueContent(issue, options);
  const checksum = await calculateDocumentChecksum({ title, content });

  return {
    id: `${context.connectorId}_issue_${issue.id}`,
    connector_id: context.connectorId,
    connector_type: context.connectorType,
    team_id: context.teamId,
    workspace_id: context.workspaceId,
    external_id: issue.id,
    document_type: "issue",
    title,
    content,
    author_name: issue.creator?.displayName,
    created_at: new Date(issue.createdAt).getTime(),
    updated_at: new Date(issue.updatedAt).getTime(),
    url: issue.url,
    is_public: false,
    access_control: [`team:${context.teamId}`],
    metadata: buildIssueMetadata(issue, options),
    checksum,
  };
}
```

Transformer rules:
- `id` format: `{connectorId}_{documentType}_{externalId}`
- `content` should be a searchable text blob with all relevant fields
- `metadata` contains structured data for filtering and display
- Always set `connector_id`, `connector_type`, `team_id`, `workspace_id`

## Step 4: Temporal Wiring

The generic `connectorSyncWorkflow` in `packages/temporal/src/workflows/sync/connector-sync.ts` handles all connectors. Wire your connector by implementing the `fetchBatch` activity.

The workflow handles:
- Batch fetching via the `fetchBatch` activity
- Document indexing via the `indexDocumentsWorkflow` child workflow
- Progress tracking with signals and queries
- `continueAsNew` when history exceeds 10,000 events
- Pause, resume, and cancel signals

Register your connector in the sync registry at `packages/temporal/src/activities/connectors/sync-registry.ts` so the generic workflow can find it.

## Testing Your Connector

Every connector needs tests in `packages/services/src/{name}/__tests__/`. At minimum:

| Test | What to verify |
|------|---------------|
| **Client tests** | Mocked HTTP responses, error handling, rate limiting |
| **Transformer tests** | Entity input produces correct `GenericDocument` output |
| **Sync generator tests** | Pagination, cursor handling, batch yielding |

```bash
bun test packages/services/src/{name}/
```

## Common Patterns

### Pagination Helper

```typescript
async function* paginate<T>(
  fetcher: (cursor?: string) => Promise<{ data: T[]; nextCursor?: string }>
): AsyncGenerator<T[]> {
  let cursor: string | undefined;
  do {
    const response = await fetcher(cursor);
    yield response.data;
    cursor = response.nextCursor;
  } while (cursor);
}
```

### User Lookup Cache

```typescript
export function createUserLookup(users: User[]): UserLookup {
  const map = new Map(users.map((u) => [u.id, u]));
  return {
    get: (id: string) => map.get(id),
    getName: (id: string) => map.get(id)?.name,
  };
}
```

### Token Refresh (OAuth)

```typescript
async function getAccessToken(connectorId: string): Promise<string> {
  const oauth = await getOAuthProvider(connectorId);
  if (isTokenExpired(oauth)) {
    const refreshed = await refreshToken(oauth);
    await updateOAuthProvider(connectorId, refreshed);
    return refreshed.accessToken;
  }
  return oauth.accessToken;
}
```
