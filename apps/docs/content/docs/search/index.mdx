# Search

One query searches everything. Slack messages, Notion pages, GitHub PRs, Linear issues, Google Drive files, meeting recordings, spreadsheets -- OpenPlane unifies them all into a single search interface, ranked by relevance and filtered by access controls.

## Three Search Modes

| Mode | When to Use | How It Works |
|------|-------------|--------------|
| **Hybrid** | General queries (default) | RRF fusion of BM25 keyword matching + dense vector similarity + sparse embeddings |
| **Semantic** | Conceptual queries without exact terms | Pure vector cosine similarity. Finds documents by meaning. |
| **Keyword** | Exact names, error codes, quoted phrases | BM25 text matching with term frequency normalization |

Hybrid is the default and the right choice 90% of the time. It catches both exact keyword matches and semantically related content, then merges the ranked lists using Reciprocal Rank Fusion.

## What Gets Indexed

Every connector normalizes its data into the `GenericDocument` schema before indexing. This is the universal format that makes cross-source search possible.

```typescript
interface GenericDocument {
  // Identity
  id: string;
  connector_id: string;
  connector_type: string;       // "slack", "notion", "github", "linear", ...
  team_id: string;
  external_id: string;
  document_type: string;        // "message", "page", "issue", "file", "email"

  // Content
  title: string;
  content: string;
  content_embedding?: number[]; // Dense vector (768 or 1024 dimensions)
  title_embedding?: number[];
  sparse_embedding?: Record<string, number>; // Learned sparse weights

  // Authorship
  author_name?: string;
  author_email?: string;
  contributor_ids?: string[];

  // Timestamps (Unix epoch ms)
  created_at: number;
  updated_at: number;

  // Metadata
  status?: string;
  priority?: string;
  labels?: string[];
  url?: string;

  // Access control
  access_control?: string[];    // User/group IDs for permission filtering
  is_public: boolean;

  // Knowledge graph
  entity_ids?: string[];
  topics?: string[];
  authority_score?: number;
  quality_score?: number;
}
```

OpenPlane indexes four document schemas in Vespa:

| Schema | Content Type | Key Fields |
|--------|-------------|------------|
| `openplane_document` | Text (messages, pages, issues, files, emails) | `content`, `content_embedding`, `sparse_embedding`, `access_control` |
| `media_document` | Video and audio (meetings, recordings) | `transcript`, `segment_embeddings`, `duration_seconds`, `segment_timestamps` |
| `spreadsheet_document` | Tabular data (sheets, CSVs) | `column_names`, `column_types`, `row_count`, `is_queryable` |
| `entity` | People, teams, projects | `entity_type`, `name`, `email` |

## Permission-Aware Results

Every result is filtered by access controls before it reaches the user. Documents the user cannot access never appear in results -- they are excluded at the Vespa content node level, before ranking even begins.

When a document is indexed, its `access_control` field captures the user and group identifiers from the source system (Slack channel membership, Google Drive sharing, Notion workspace access). At query time, the user's IDs are matched against this field:

```sql
AND (is_public = true
  OR access_control CONTAINS "user:jane"
  OR access_control CONTAINS "group:finance")
```

## Ranking Profiles

Vespa applies different ranking strategies depending on the query type.

| Profile | Use Case |
|---------|----------|
| `hybrid` | General-purpose search (default) |
| `hybrid_v2` | Enhanced hybrid with sparse embedding signals |
| `semantic` | Pure vector similarity for conceptual queries |
| `bm25` | Keyword-only matching for exact terms |
| `enterprise` | Hybrid + authority score + recency boost |
| `enterprise_v2` | Production enterprise with sparse vectors |
| `recency` | Prioritizes recently updated documents |
| `hybrid_recency` | Hybrid ranking with time decay |
| `navigational` | Finding a specific known document by title |
| `personalized` | Boosts results matching user department affinity |
| `authority` | Ranks by inbound links, quality score, source tier |
| `topic_search` | Topic-level vector similarity |
| `engagement` | View count, reactions, access frequency |

## Media Search

Video and audio content is indexed with segment-level granularity. You can search meeting transcripts, find the exact moment someone discussed a topic, or discover screen content via OCR.

| Signal | Description |
|--------|-------------|
| `transcript` | Full transcript text, BM25-searchable |
| `segment_embeddings` | Per-segment vectors for temporal precision |
| `segment_speakers` | Speaker identification per segment |
| `segment_ocr_text` | OCR from screen recordings |
| `media_keywords` | Extracted topic keywords |

Ranking profiles for media: `meeting_search`, `screen_content`, `unified_text`, `engagement`.

## Edge Search

For offline and air-gapped deployments, the edge runtime provides local search using SQLite FTS5 and in-process vector similarity. Same query interface, runs entirely on-device.

```typescript
import { SearchEngine } from "@openplane/edge-search";

const engine = new SearchEngine(db);
const results = await engine.search("deployment checklist", {
  mode: "hybrid",
  limit: 10,
});
```

Documents sync incrementally via Merkle tree reconciliation when connectivity is available.

## Search Tools for Agents

All search capabilities are exposed as agent tools:

| Tool | Description |
|------|-------------|
| `search_hybrid` | Hybrid semantic + keyword search across all sources |
| `search_semantic` | Pure vector search for conceptual queries |
| `search_similar` | Find documents related to a known document by ID |
| `search_web` | Web search for external information |
| `search_export` | Export search results in structured format |
| `search_save` | Bookmark search results for later |
| `scrape_page` | Fetch and parse a web page |

These tools are available to all agent patterns and via the [MCP server](/docs/ai/mcp) for external AI clients.
