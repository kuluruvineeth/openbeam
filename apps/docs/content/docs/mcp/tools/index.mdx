# Tools Reference

OpenBeam exposes 20 MCP tools organized into 6 categories. Every tool is available through the MCP protocol to Claude Desktop, Cursor, Claude Code, and any other MCP-compatible client.

Tools follow a progressive discovery pattern: list available resources, inspect details, then act. Most workflows chain 2-3 tools together.

## Tool Chaining

Most tasks require chaining multiple tools. Here are the common patterns:

| Goal | Tool Chain |
|------|------------|
| Answer a question | `ask_question` &rarr; `context_read` (for citation details) |
| Research a topic | `search_documents` &rarr; `context_read` &rarr; `search_people` (for experts) |
| Diagnose connector issues | `connector_list` (filter: error) &rarr; `connector_health` &rarr; `sync_history` |
| Refresh data | `connector_list` &rarr; `sync_trigger` &rarr; `sync_status` |
| Send a message / create issue | `connector_actions_list` &rarr; `connector_action_execute` |
| Set up a new connector | `connector_available` &rarr; `connector_setup` or `connector_configure` &rarr; `sync_trigger` |
| Team overview | `team_info` &rarr; `team_members` &rarr; `connector_list` |

## Authentication

Every MCP request must include an API key in the `Authorization` header:

```
Authorization: Bearer op_live_...
```

API keys are created in Settings and carry the scopes that determine which tools are available. A key without `sync.write` scope will not see the `sync_trigger` tool.

## Response Format

All tools return two fields:

- **`content`** -- Text formatted for the LLM. Human-readable summaries with chaining hints.
- **`structuredContent`** -- JSON data for UI rendering. Hidden from the LLM, consumed by MCP app views.

List responses include pagination metadata:

```json
{
  "meta": { "cursor": "next_id", "hasNextPage": true, "totalResults": 142 },
  "data": [...]
}
```
