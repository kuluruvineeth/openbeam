# Action Tools

Two tools implementing a progressive discovery pattern for write operations across connected data sources. First discover available actions with `connector_actions_list`, then execute with `connector_action_execute`.

<Callout type="info">
Always call `connector_actions_list` first to discover the exact action ID and required parameters before calling `connector_action_execute`.
</Callout>

## connector_actions_list

Discover available write actions for connected data sources. Lists operations like sending Slack messages, creating Jira issues, creating Notion pages, and more. Each action includes its ID, description, required parameters, stakes level, and reversibility.

Requires `connectors.read` scope.

### Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `connectorType` | `string` | No | Filter by connector type (e.g. `slack`, `linear`, `notion`). Omit to list all. |
| `category` | `string` | No | Filter by category: `create`, `read`, `update`, `delete`, `search`, `list`, `notify` |

### Response

Each action contains:

| Field | Type | Description |
|-------|------|-------------|
| `id` | `string` | Action ID (e.g. `message_send`, `issue_create`) |
| `name` | `string` | Human-readable action name |
| `description` | `string` | What the action does |
| `connectorType` | `string` | Connector type this action belongs to |
| `category` | `string` | Action category |
| `stakes` | `string` | Risk level: `low`, `medium`, `high` |
| `reversible` | `boolean` | Whether the action can be undone |
| `inputs` | `array` | Required and optional input parameters |
| `inputs[].id` | `string` | Parameter ID (used as key in `params`) |
| `inputs[].name` | `string` | Human-readable parameter name |
| `inputs[].type` | `string` | Parameter type (`string`, `number`, `boolean`, etc.) |
| `inputs[].required` | `boolean` | Whether the parameter is required |
| `inputs[].description` | `string` | Parameter description |

### Example

```json
{
  "connectorType": "linear",
  "category": "create"
}
```

### Chaining

- Use `connector_list` to find the connector ID needed for `connector_action_execute`.
- Use the `inputs` array to construct the `params` object for execution.

## connector_action_execute

Execute a write action on a connected data source. Requires three parameters: the connector instance ID, the action ID, and a params object whose keys match the input IDs from `connector_actions_list`.

Requires `connectors.write` scope.

<Callout type="warn">
Always confirm with the user before executing high-stakes or irreversible actions. Check the `stakes` and `reversible` fields from `connector_actions_list`.
</Callout>

### Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `connectorId` | `string` | Yes | ID of the connected connector instance (from `connector_list`) |
| `actionId` | `string` | Yes | Action ID (from `connector_actions_list`, e.g. `message_send`, `issue_create`) |
| `params` | `object` | Yes | Action parameters -- keys match the input IDs from `connector_actions_list` |

### Response

| Field | Type | Description |
|-------|------|-------------|
| `success` | `boolean` | Whether the action succeeded |
| `data` | `object` | Action-specific response data (e.g. created issue ID, sent message ID) |
| `error` | `string` | Error message if the action failed |

### Examples

**Create a Linear issue:**

```json
{
  "connectorId": "conn_linear_abc",
  "actionId": "issue_create",
  "params": {
    "title": "Fix search ranking for recent documents",
    "teamId": "TEAM-1",
    "priority": 2,
    "description": "Recent documents should rank higher in search results."
  }
}
```

**Send a Slack message:**

```json
{
  "connectorId": "conn_slack_xyz",
  "actionId": "message_send",
  "params": {
    "channel": "C0123456789",
    "text": "Deploy completed successfully."
  }
}
```

**Create a Notion page:**

```json
{
  "connectorId": "conn_notion_def",
  "actionId": "page_create",
  "params": {
    "parentId": "db_123",
    "title": "Meeting Notes - Q2 Planning",
    "content": "## Agenda\n\n1. Review Q1 metrics\n2. Set Q2 goals"
  }
}
```

## Connector Action Status

Every handler has been audited against real third-party API documentation. The table below reflects the verification status as of April 2026.

### Verified (63 connectors)

All endpoints, HTTP methods, request body formats, and response fields confirmed correct against official API documentation. These connectors are production-ready.

### Implemented from Research (8 connectors)

Originally stubbed, then reimplemented after researching the real API documentation. Endpoints match official docs but have not been tested against live instances.

| Connector | API Source | Notes |
|-----------|-----------|-------|
| Evernote | Official Thrift SDK (`evernote` npm) | Uses NoteStore Thrift RPC, not REST |
| Fellow | [developers.fellow.ai](https://developers.fellow.ai) | Actions limited to `action_item_complete` and `action_item_archive` (API is read-heavy) |
| Interact | [developer.interactsoftware.com](https://developer.interactsoftware.com) | Uses `/page/composer` endpoint with PascalCase fields |
| Loopio | Microsoft Power Platform connector docs | Uses OAuth 2.0 + JSON Patch for updates |
| Simpplr | [developer.simpplr.com](https://developer.simpplr.com) | Uses centralized `api.ec.simpplr.com` with OAuth + `x-user-email` header |
| LumApps | [lumapps-sdk](https://github.com/lumapps/lumapps-sdk) Python SDK source | Uses Google App Engine v1 endpoints (`/_ah/api/lumsites/v1/`) with language maps |
| Mindtickle | Official API docs (authenticated) | Uses JWT-signed auth (HS256) with `/openapi/` and `/services/data/v2.0/mtobjects/` paths |
| Haystack | Corrected domain references | No write API exists; stub returns clear error |

### Read-Only / No Write API (3 connectors)

These platforms genuinely do not expose write operations via their APIs. The handlers return descriptive error messages explaining why.

| Connector | Reason |
|-----------|--------|
| Gong | Call recording platform with read-only API. No write endpoints exist. |
| S3 | Configured in read-only mode. Write operations require explicit bucket policy changes. |
| Samsara (alert resolve) | The `POST /fleet/alerts/{id}/resolve` endpoint does not exist in Samsara's public API. Alert management is handled through the Samsara dashboard. |

### Best-Effort / Private APIs (8 connectors)

These connectors target enterprise platforms with API documentation behind customer authentication portals. Implementations follow standard REST conventions and match available public references (SDK source code, community integrations, partner documentation), but exact endpoint paths and field names have not been verified against official docs.

| Connector | Public Evidence | Risk |
|-----------|----------------|------|
| inSided (Gainsight Communities) | Singer tap, Python SDK on GitHub | Medium — `/posts` may be `/topics` in v2 |
| Klue | MCP server blog confirms write capability | Medium — base URL `api.klue.com/v1` is assumed |
| NICE CXone | Base URL and auth pattern confirmed | Low — specific action paths unverified |
| Bynder | Partial SDK docs | Low — `addAssetToCollection` body format unverified |
| Coupa | Enterprise-only docs | Low — endpoint paths match known patterns |
| Docebo | Community posts reference endpoints | Low — enrollment path may differ |
| 15Five | Limited public docs | Low — field names (`sender`/`receiver`) may be IDs |
| Verkada | Physical security API | Medium — `lock` endpoint may not exist (doors auto-lock) |

<Callout type="warn">
If you encounter errors with any best-effort connector, the issue is likely an incorrect endpoint path or field name. Open an issue with the error message and we will fix it against the real API docs.
</Callout>
