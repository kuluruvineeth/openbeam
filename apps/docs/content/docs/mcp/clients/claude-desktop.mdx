# Claude Desktop

Claude Desktop supports the Model Context Protocol (MCP) natively, allowing OpenBeam to surface enterprise search, connector management, sync operations, and write actions directly inside your Claude conversations. Because Claude Desktop also supports `ext-apps`, OpenBeam renders rich UI cards alongside text responses.

## Prerequisites

- **Claude Desktop** installed ([macOS](https://claude.ai/download) or [Windows](https://claude.ai/download))
- An **OpenBeam account** with at least one connected data source

## Configuration

Claude Desktop supports OAuth natively. Just add the server URL and sign in — no API key needed.

<Tabs items={["OAuth (Recommended)", "API Key"]}>
<Tab value="OAuth (Recommended)">

<Steps>
<Step>

### Add OpenBeam

In any Claude Desktop chat, click the **+** button, then **Connectors > Manage Connectors > Add custom server**:

```
https://api.openbeam.work/mcp
```

</Step>
<Step>

### Authorize

Claude opens the OpenBeam sign-in page. Log in with your OpenBeam account and click **Authorize**. Done — OpenBeam's 20 tools appear immediately.

</Step>
</Steps>

</Tab>
<Tab value="API Key">

<Steps>
<Step>

### Locate the config file

Open Claude Desktop, go to **Settings > Developer > Edit Config**. This opens the config file in your default editor and creates it if it does not exist. The path depends on your operating system.

<Tabs items={["macOS", "Windows"]}>
  <Tab value="macOS">
  ```text
  ~/Library/Application Support/Claude/claude_desktop_config.json
  ```

  Open it in your editor:

  ```bash
  open -a "TextEdit" ~/Library/Application\ Support/Claude/claude_desktop_config.json
  ```

  If the file does not exist, create it.
  </Tab>
  <Tab value="Windows">
  ```text
  %APPDATA%\Claude\claude_desktop_config.json
  ```

  Open it in your editor:

  ```powershell
  notepad "$env:APPDATA\Claude\claude_desktop_config.json"
  ```

  If the file does not exist, create it.
  </Tab>
</Tabs>

</Step>
<Step>

### Add the OpenBeam server

Add the following to the config file. If the file already contains other MCP servers, merge the `openbeam` key into the existing `mcpServers` object.

```json
{
  "mcpServers": {
    "openbeam": {
      "url": "https://api.openbeam.work/mcp",
      "headers": {
        "Authorization": "Bearer op_live_your_key_here"
      }
    }
  }
}
```

Replace `op_live_your_key_here` with your actual API key.

<Callout type="warn">
If you self-host OpenBeam, replace `https://api.openbeam.work` with your server's base URL.
</Callout>

</Step>
<Step>

### Restart Claude Desktop

Quit Claude Desktop completely and reopen it. The MCP server connects on startup.

</Step>
</Steps>

</Tab>
</Tabs>

## Verification

After restarting, open a new conversation and type:

```text
List my connectors
```

Claude should invoke the `connector_list` tool and return a summary of your connected data sources. If you see connector names, statuses, and document counts, the integration is working.

You can also click the **MCP tools** icon (hammer) in the bottom-left of the composer to confirm that OpenBeam tools appear in the list.

## Rich UI Views

Claude Desktop supports `ext-apps`, so OpenBeam renders interactive UI cards alongside text responses. These appear automatically when you invoke the relevant tools.

| View | What it shows | Triggered by |
|------|---------------|-------------|
| Search results | Source icons, titles, snippets, relevance scores | Searching for documents |
| Connector dashboard | Status badges, document counts, last sync times | Listing connectors |
| Document preview | Full content with metadata and source link | Reading a specific document |
| Sync status | Progress indicators, job state, error details | Checking or triggering syncs |
| People directory | Avatars, roles, expertise areas, contact info | Searching for people |
| Connector setup | Browse available connectors, OAuth flow, API key entry | Connecting a new data source |
| Team overview | Member list, roles, connected sources count | Asking about your team |

<Callout type="info">
Rich UI cards are rendered in a sandboxed iframe. The data powering them comes from `structuredContent` returned by each tool — the same data Claude sees as text is also rendered visually.
</Callout>

## Troubleshooting

### MCP server not appearing

<Steps>
<Step>
Confirm the config file is valid JSON. A trailing comma or missing bracket will silently prevent loading. Paste the file contents into a JSON validator if unsure.
</Step>
<Step>
Verify the file path is correct for your OS (see the Configuration section above).
</Step>
<Step>
Restart Claude Desktop completely — closing the window is not enough on macOS. Use **Claude > Quit Claude** from the menu bar.
</Step>
</Steps>

### Authentication failed

- Double-check that your API key starts with `op_live_` and has not been revoked.
- Ensure there are no extra spaces or line breaks inside the key value.
- If you self-host, confirm your server is reachable from your machine: `curl -s https://your-server/mcp` should return a response (not a connection error).

### Tools not loading

- Some tools are gated by scopes assigned to your API key. If you only see a subset of tools, check the key's scope configuration in **Settings > API Keys**.
- If no tools appear at all, the server connection likely failed. Check the Claude Desktop developer console (**Help > Developer Tools**) for network errors.

### Rich UI cards not rendering

- Rich UI requires Claude Desktop version 1.5 or later. Update to the latest version.
- If cards appear blank, check for content-security-policy errors in the developer console — a corporate proxy may be blocking the sandboxed iframe resources.
