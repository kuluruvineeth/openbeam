# MCP Server

OpenPlane implements a [Model Context Protocol](https://modelcontextprotocol.io/) (MCP) server that exposes its tool registry, resources, and prompt templates to external AI clients like Claude Desktop, Cursor, or any MCP-compatible application.

## Overview

The MCP server bridges OpenPlane's internal tool system with the MCP specification (JSON-RPC 2.0). It automatically converts registered tools into MCP-compatible definitions, handles capability negotiation, and manages request routing.

```
┌─────────────────────────┐         ┌────────────────────────┐
│  External AI Client      │         │  OpenPlane MCP Server   │
│  (Claude Desktop, etc.)  │  MCP    │                        │
│                          │◄───────►│  Tools (from registry)  │
│  tools/list              │         │  Resources (docs, etc.) │
│  tools/call              │         │  Prompts (templates)    │
│  resources/read          │         │                        │
│  prompts/get             │         │  MCPToolBridge          │
└─────────────────────────┘         └────────────────────────┘
```

## Creating the Server

```typescript
import { createMCPServer, toolRegistry } from "@openplane/ai";

const server = createMCPServer(toolRegistry, {
  name: "openplane",
  version: "1.0.0",
  capabilities: {
    tools: true,
    resources: true,
    prompts: true,
    logging: false,
    sampling: false,
  },
});
```

## Capabilities

The server supports three primary MCP capabilities:

| Capability | Description |
|------------|-------------|
| **Tools** | All registered tools from the `toolRegistry`, filtered by `allowedCallers: ["mcp"]` |
| **Resources** | Document resources, connector status, team profiles, search results |
| **Prompts** | Pre-built prompt templates for enterprise search, analysis, and summarization |

Capabilities are negotiated during the `initialize` handshake. The server only enables capabilities that both sides support.

## Request Handling

The server routes JSON-RPC 2.0 requests to the appropriate handler:

```typescript
// Handle incoming MCP requests
const response = await server.handleRequest(request, {
  teamId: "team_123",
  userId: "user_456",
});

// Handle notifications (no response expected)
server.handleNotification(notification, context);
```

### Supported Methods

| Method | Description |
|--------|-------------|
| `initialize` | Capability negotiation and handshake |
| `initialized` | Client confirms initialization |
| `ping` | Health check (returns `{ pong: true }`) |
| `tools/list` | List all available tools with schemas |
| `tools/call` | Execute a tool by name with arguments |
| `resources/list` | List available resources |
| `resources/templates/list` | List resource URI templates |
| `resources/read` | Read a resource by URI |
| `prompts/list` | List available prompts |
| `prompts/get` | Get a prompt by name with arguments |

## Tool Bridge

The `MCPToolBridge` converts OpenPlane's internal tool definitions to MCP format:

```typescript
import { MCPToolBridge, toolRegistry } from "@openplane/ai";

const bridge = new MCPToolBridge(toolRegistry);

// List tools in MCP format
const tools = bridge.listTools();
// Returns: Array<{ name, description, inputSchema, pricing? }>

// Execute a tool
const result = await bridge.executeTool(
  { name: "search_hybrid", arguments: { query: "API docs", limit: 10 } },
  mcpContext
);
```

### Schema Conversion

Zod schemas are automatically converted to JSON Schema for MCP compatibility:

```typescript
import { convertZodToJsonSchema } from "@openplane/ai";

// Zod 4's toJSONSchema() is used when available
const jsonSchema = convertZodToJsonSchema(zodSchema);
```

### Context Mapping

MCP server context is mapped to OpenPlane's `ToolContext`:

```typescript
import { mcpContextToToolContext } from "@openplane/ai";

const toolContext = mcpContextToToolContext(mcpServerContext, services);
// Maps teamId, userId, accessControl from MCP context
```

## Resources

Resources expose OpenPlane data to MCP clients for context grounding.

### Built-in Resources

```typescript
import {
  defineUserContextResource,
  defineTeamProfileResource,
  defineConnectorsResource,
  defineRecentDocumentsResource,
} from "@openplane/ai";
```

| Resource | URI | Description |
|----------|-----|-------------|
| User Context | `openplane://user/context` | Current user preferences and activity |
| Team Profile | `openplane://team/profile` | Team configuration and settings |
| Connectors | `openplane://connectors` | List of connected data sources with status |
| Recent Documents | `openplane://documents/recent` | Recently accessed documents |
| Team Stats | `openplane://team/stats` | Team usage and activity statistics |
| Memory Stats | `openplane://memory/stats` | Agent memory statistics |

### Resource Templates

URI templates for parameterized resource access:

```typescript
import {
  defineDocumentResourceTemplate,
  defineSearchResultsResourceTemplate,
  defineConnectorResourceTemplate,
  defineConnectorSyncHistoryTemplate,
} from "@openplane/ai";
```

| Template | URI Pattern | Description |
|----------|-------------|-------------|
| Document | `openplane://documents/{id}` | Read a specific document |
| Search Results | `openplane://search/{query}` | Execute a search query |
| Connector | `openplane://connectors/{id}` | Connector details and config |
| Sync History | `openplane://connectors/{id}/sync-history` | Connector sync history |

### Custom Resources

Register additional resources:

```typescript
const resourceRegistry = server.getResourceRegistry();

resourceRegistry.register({
  uri: "openplane://custom/dashboard",
  name: "Dashboard Data",
  description: "Current dashboard metrics",
  mimeType: "application/json",
  handler: async (uri, context) => ({
    contents: [{
      uri,
      mimeType: "application/json",
      text: JSON.stringify(await getDashboardData(context.teamId)),
    }],
  }),
});
```

## Prompts

Pre-built prompt templates for common enterprise tasks.

### Built-in Prompts

```typescript
import {
  defineEnterpriseSearchPrompt,
  defineDocumentSummaryPrompt,
  defineAnalyzeDocumentsPrompt,
  defineAnswerQuestionPrompt,
  defineExplainConnectorPrompt,
  defineFindExpertPrompt,
} from "@openplane/ai";
```

| Prompt | Arguments | Description |
|--------|-----------|-------------|
| `enterprise_search` | `query` | Search across connected sources with citations |
| `document_summary` | `documentId`, `style?` | Summarize a specific document |
| `analyze_documents` | `query`, `documentIds` | Analyze multiple documents |
| `answer_question` | `question`, `context?` | Answer a question with RAG |
| `explain_connector` | `connectorType` | Explain a connector's capabilities |
| `find_expert` | `topic` | Find team members knowledgeable about a topic |

### Custom Prompts

Register custom prompts:

```typescript
const promptRegistry = server.getPromptRegistry();

promptRegistry.register({
  name: "weekly_report",
  description: "Generate a weekly activity report",
  arguments: [
    { name: "startDate", description: "Report start date (ISO)", required: true },
    { name: "endDate", description: "Report end date (ISO)", required: false },
  ],
  handler: async (args, context) => ({
    messages: [
      {
        role: "user",
        content: {
          type: "text",
          text: `Generate a weekly activity report for ${args.startDate} to ${args.endDate ?? "now"}.`,
        },
      },
    ],
  }),
});
```

## Error Handling

MCP errors follow the JSON-RPC 2.0 error spec:

| Code | Name | Description |
|------|------|-------------|
| `-32700` | Parse Error | Invalid JSON |
| `-32600` | Invalid Request | Malformed request |
| `-32601` | Method Not Found | Unknown method |
| `-32602` | Invalid Params | Invalid method parameters |
| `-32603` | Internal Error | Server-side error |
| `-32001` | Tool Not Found | Requested tool does not exist |
| `-32002` | Resource Not Found | Requested resource does not exist |
| `-32003` | Prompt Not Found | Requested prompt does not exist |

## Message Utilities

Helper functions for building and parsing MCP messages:

```typescript
import {
  createRequest,
  createNotification,
  isValidRequest,
  isValidNotification,
  parseMessage,
} from "@openplane/ai";

// Build a request
const request = createRequest("tools/call", {
  name: "search_hybrid",
  arguments: { query: "API docs" },
});

// Parse incoming JSON
const message = parseMessage(jsonString);
if (isValidRequest(message)) {
  const response = await server.handleRequest(message, context);
}
```

## Connecting Claude Desktop

To connect OpenPlane as an MCP server in Claude Desktop, add to your Claude Desktop configuration:

```json
{
  "mcpServers": {
    "openplane": {
      "command": "openplane",
      "args": ["mcp", "serve"],
      "env": {
        "OPENPLANE_API_URL": "http://localhost:3000",
        "OPENPLANE_API_KEY": "your-api-key"
      }
    }
  }
}
```

The OpenPlane CLI (`apps/cli`) includes a built-in `mcp serve` command that starts an MCP server over stdio, making it compatible with any MCP client that supports the stdio transport.
