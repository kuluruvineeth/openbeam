# MCP Server

OpenPlane implements a [Model Context Protocol](https://modelcontextprotocol.io/) (MCP) server that exposes its tools, resources, and prompt templates to external AI clients. Any MCP-compatible application -- Claude Desktop, Cursor, Windsurf, or custom clients -- can search your organization's knowledge base, retrieve documents, and run analyses through OpenPlane.

## Server Setup

```typescript
import { createMCPServer, toolRegistry } from "@openplane/ai";
import { registerDefaultPrompts } from "@openplane/ai/mcp/prompts";
import { getDefaultResourceDefinitions, getDefaultResourceTemplates } from "@openplane/ai/mcp/resources";

const server = createMCPServer(toolRegistry, {
  name: "openplane",
  version: "1.0.0",
  capabilities: {
    tools: true,
    resources: true,
    prompts: true,
    logging: false,
    sampling: false,
  },
});

// Register resources
const resources = server.getResourceRegistry();
for (const def of getDefaultResourceDefinitions()) {
  resources.register(def, resourceHandler);
}
for (const template of getDefaultResourceTemplates()) {
  resources.registerTemplate(template, templateHandler);
}

// Register prompt templates
registerDefaultPrompts(server.getPromptRegistry());
```

## Protocol

The MCP server uses JSON-RPC 2.0 over stdio or HTTP. It handles the full MCP lifecycle:

| Method | Description |
|--------|-------------|
| `initialize` | Capability negotiation and handshake |
| `ping` | Health check |
| `tools/list` | List all available tools with schemas |
| `tools/call` | Execute a tool with arguments |
| `resources/list` | List static resources |
| `resources/templates/list` | List URI-templated resources |
| `resources/read` | Read a specific resource by URI |
| `prompts/list` | List available prompt templates |
| `prompts/get` | Get a rendered prompt with arguments |

## Tools

Every tool registered in the `toolRegistry` with `allowedCallers: ["mcp"]` (the default) is automatically exposed via MCP. The `MCPToolBridge` converts Zod schemas to JSON Schema and wraps execution results.

### Available Tools

All [search](/docs/ai/tools#tool-categories), [RAG](/docs/ai/rag), [document](/docs/ai/tools#tool-categories), and [connector](/docs/ai/tools#tool-categories) tools are available via MCP. Key tools:

| Tool | Category | Description |
|------|----------|-------------|
| `search_hybrid` | search | Hybrid semantic + keyword search across all sources |
| `search_semantic` | search | Pure vector similarity search |
| `search_similar` | search | Find documents similar to a given document |
| `search_web` | search | Web search for external information |
| `doc_get` | documents | Retrieve a document by ID |
| `doc_list` | documents | List documents with filters |
| `doc_chunks` | documents | Get chunks of a document |
| `rag_answer` | rag | Generate grounded answer with citations |
| `rag_analyze` | rag | Analyze a query's intent and entities |
| `rag_verify` | rag | Verify claims against source material |
| `connector_list` | connectors | List connected data sources |
| `connector_status` | connectors | Check connector sync status |
| `connector_sync` | connectors | Trigger a sync for a connector |

### Tool Execution

When an MCP client calls a tool, the bridge:

1. Validates the tool exists and allows MCP callers
2. Converts the MCP context to a `ToolContext` with team/user identity
3. Executes the tool via the Vercel AI SDK's tool execution layer
4. Converts the `ToolExecutionResult` to MCP format

```typescript
// MCP request
{
  "jsonrpc": "2.0",
  "id": "1",
  "method": "tools/call",
  "params": {
    "name": "search_hybrid",
    "arguments": { "query": "deployment process", "limit": 5 }
  }
}

// MCP response
{
  "jsonrpc": "2.0",
  "id": "1",
  "result": {
    "content": [{ "type": "text", "text": "{\"results\": [...], \"totalCount\": 42}" }],
    "isError": false
  }
}
```

### Priced Tools

Tools with pricing metadata include cost information in their MCP listing:

```typescript
{
  name: "search_hybrid",
  description: "...",
  inputSchema: { ... },
  pricing: {
    amount: "0.01",
    currency: "USDC",
    network: "eip155:84532",
    description: "Per search query"
  }
}
```

## Resources

MCP resources give AI clients read access to OpenPlane data without tool calls.

### Static Resources

| URI | Name | Description |
|-----|------|-------------|
| `openplane://connectors` | Connected Sources | All active data source integrations |
| `openplane://documents/recent` | Recent Documents | Documents indexed in the last 24 hours |
| `openplane://team/profile` | Team Profile | Team settings and configuration |
| `openplane://user/context` | User Context | Current user permissions and preferences |

### URI Templates

| Template | Name | Description |
|----------|------|-------------|
| `openplane://documents/{documentId}` | Document | Full content of a document by ID |
| `openplane://search/{queryId}` | Search Results | Cached search results for a query ID |

### Reading Resources

```typescript
// MCP request
{
  "jsonrpc": "2.0",
  "id": "2",
  "method": "resources/read",
  "params": { "uri": "openplane://connectors" }
}

// Response contains the resource content
{
  "jsonrpc": "2.0",
  "id": "2",
  "result": {
    "contents": [{
      "uri": "openplane://connectors",
      "text": "[{\"id\": \"conn_1\", \"type\": \"slack\", \"status\": \"active\"}]",
      "mimeType": "application/json"
    }]
  }
}
```

## Prompts

MCP prompts provide pre-built prompt templates that AI clients can use to structure interactions with OpenPlane.

| Prompt | Arguments | Description |
|--------|-----------|-------------|
| `enterprise-search` | `query` (required), `sources`, `limit` | Search across all connected data sources |
| `document-summary` | `documentId` (required), `length` | Summarize a document (brief/standard/detailed) |
| `answer-question` | `question` (required), `context` | Answer a question with citations from the knowledge base |
| `analyze-documents` | `documentIds` (required), `analysisType` | Analyze documents for themes, entities, timeline, or comparison |
| `explain-connector` | `connectorType` (required) | Explain a connector's capabilities and data sync behavior |
| `find-expert` | `topic` (required) | Find team members with expertise in a topic |

### Using Prompts

```typescript
// MCP request
{
  "jsonrpc": "2.0",
  "id": "3",
  "method": "prompts/get",
  "params": {
    "name": "answer-question",
    "arguments": {
      "question": "What is our deployment process?",
      "context": "Looking for the staging deployment specifically"
    }
  }
}

// Response contains rendered prompt messages
{
  "jsonrpc": "2.0",
  "id": "3",
  "result": {
    "messages": [{
      "role": "user",
      "content": {
        "type": "text",
        "text": "Answer this question using the enterprise knowledge base: \"What is our deployment process?\" Additional context: Looking for the staging deployment specifically. Cite specific documents as sources."
      }
    }]
  }
}
```

## Claude Desktop Integration

Add OpenPlane as an MCP server in Claude Desktop's configuration:

```json
{
  "mcpServers": {
    "openplane": {
      "command": "openplane",
      "args": ["mcp", "serve"],
      "env": {
        "OPENPLANE_API_URL": "https://your-instance.openplane.dev",
        "OPENPLANE_API_KEY": "op_key_..."
      }
    }
  }
}
```

Once configured, Claude Desktop can:

- Search your organization's documents with `search_hybrid`
- Read specific documents with `doc_get`
- Answer questions grounded in your knowledge base with `rag_answer`
- List connected data sources with `connector_list`
- Use prompt templates for structured interactions

## Custom MCP Clients

Any MCP-compatible client can connect to the OpenPlane server. The server handles:

- **Capability negotiation** -- Clients declare which capabilities they support, and the server intersects with its own capabilities
- **Request routing** -- Dispatches to the appropriate handler (tools, resources, or prompts)
- **Error classification** -- Maps internal errors to MCP error codes

```typescript
import { parseMessage, isValidRequest, isValidNotification } from "@openplane/ai/mcp";

const message = parseMessage(jsonString);

if (isValidRequest(message)) {
  const response = await server.handleRequest(message, {
    teamId: "team_123",
    userId: "user_456",
  });
  send(JSON.stringify(response));
}

if (isValidNotification(message)) {
  server.handleNotification(message, context);
}
```

### MCP Error Codes

| Code | Name | Description |
|------|------|-------------|
| `-32700` | Parse error | Invalid JSON |
| `-32600` | Invalid request | Missing required fields |
| `-32601` | Method not found | Unknown MCP method |
| `-32602` | Invalid params | Invalid method parameters |
| `-32603` | Internal error | Server-side error |
| `-32001` | Tool not found | Requested tool does not exist |
| `-32002` | Resource not found | Requested resource does not exist |
| `-32003` | Prompt not found | Requested prompt does not exist |

## Architecture

```
External AI Client               OpenPlane
┌─────────────────┐             ┌──────────────────────────────┐
│ Claude Desktop  │             │  MCPServer                   │
│ Cursor          │  JSON-RPC   │  ├── MCPToolBridge            │
│ Custom Client   │◄───────────►│  │   └── ToolRegistry        │
│                 │   2.0       │  ├── ResourceRegistry         │
│ tools/call      │             │  │   ├── Static resources     │
│ resources/read  │             │  │   └── URI templates         │
│ prompts/get     │             │  └── PromptRegistry           │
└─────────────────┘             │      └── 6 prompt templates   │
                                └──────────────────────────────┘
```

The `MCPToolBridge` automatically converts the internal `ToolRegistry` format to MCP-compatible tool definitions. When a tool is registered or unregistered in the registry, it is immediately reflected in MCP's `tools/list` response.
