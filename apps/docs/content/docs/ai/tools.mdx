# Tool Framework

Tools are atomic capabilities that agents invoke to interact with the world. Every tool is defined with a Zod schema, registered in the global `toolRegistry`, and made available to both agents and external MCP clients.

## Defining a Tool

Use `defineTool()` to create a typed, self-registering tool:

```typescript
import { defineTool, success, failure, z } from "@openplane/ai";

export const searchHybridTool = defineTool({
  name: "search_hybrid",
  description: `Search across all connected enterprise data sources using hybrid
semantic + keyword search.

USE THIS WHEN:
- User asks a question requiring information from the knowledge base
- Query contains specific keywords, names, or exact phrases
- Research tasks requiring comprehensive results

DO NOT USE WHEN:
- User wants conceptually similar documents (use search_semantic)
- User needs a specific known document (use doc_get)

RETURNS: Ranked list of documents with relevance scores, snippets, and source metadata.`,

  category: "search",
  parameters: z.object({
    query: z.string().min(1).describe("The search query"),
    limit: z.number().min(1).max(100).optional().default(10)
      .describe("Max results (1-100)"),
    filters: z.object({
      connectorTypes: z.array(z.string()).optional()
        .describe("Filter by source: 'slack', 'notion', 'github', etc."),
      dateRange: z.object({
        start: z.string().optional().describe("ISO 8601 date"),
        end: z.string().optional().describe("ISO 8601 date"),
      }).optional(),
      authors: z.array(z.string()).optional()
        .describe("Filter by author name or email"),
    }).optional(),
  }),

  async execute(params, ctx) {
    if (!ctx.teamId) {
      return failure("UNAUTHORIZED", "Team context required");
    }

    const result = await ctx.services.search.hybrid({
      query: params.query,
      teamId: ctx.teamId,
      limit: params.limit,
      connectorTypes: params.filters?.connectorTypes,
      accessControlIds: ctx.accessControl,
    });

    return success({
      results: result.documents.map(doc => ({
        id: doc.id,
        title: doc.title,
        snippet: doc.content?.slice(0, 300),
        score: doc.relevanceScore,
        source: doc.connectorType,
        url: doc.url,
      })),
      totalCount: result.total,
    }, { latencyMs: result.queryTime, source: "vespa" });
  },
});

searchHybridTool.register();
```

## `defineTool()` API Reference

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | `string` | Yes | Unique tool identifier. Convention: `verb_noun` (e.g., `search_hybrid`). |
| `description` | `string` | Yes | What the tool does. Include USE/DON'T USE/RETURNS sections for agent guidance. |
| `category` | `ToolCategory` | Yes | One of 14 categories (see table below). |
| `parameters` | `z.ZodType` | Yes | Zod schema for input validation. Field `.describe()` is critical for agents. |
| `execute` | `(params, ctx) => ToolExecutionResult` | Yes | The implementation. Receives validated params and `ToolContext`. |
| `deferLoading` | `boolean` | No | If `true`, tool is not loaded by default -- agents must request it explicitly. |
| `searchKeywords` | `string[]` | No | Additional keywords for tool discovery search. |
| `requiredPermissions` | `string[]` | No | Permission IDs the user must have to use this tool. |
| `allowedCallers` | `AllowedCaller[]` | No | Who can invoke: `"agent"`, `"mcp"`, `"ui"`. Default: `["agent", "mcp"]`. |
| `cacheTtlMs` | `number` | No | Cache TTL for results. |
| `cacheKeyFn` | `(params) => string` | No | Custom cache key function. |
| `stakes` | `StakesLevel` | No | `"low"`, `"medium"`, `"high"`. Affects approval requirements. |
| `reversibility` | `ReversibilityLevel` | No | `"easy"`, `"hard"`, `"irreversible"`. Affects approval requirements. |
| `approval` | `ApprovalPattern` | No | Override auto-derived approval pattern. |
| `pricing` | `object` | No | Per-invocation pricing for paid tools. |

## Result Helpers

Every tool must return a `ToolExecutionResult`. Use the `success()` and `failure()` helpers:

```typescript
// Success with data and metadata
return success(data, { latencyMs: 42, source: "vespa" });

// Failure with error code
return failure("NOT_FOUND", "Document not found");

// Failure with options
return failure("RATE_LIMITED", "Too many requests", {
  retryable: true,
  suggestion: "Wait 30 seconds and try again",
});
```

**Result shape:**

```typescript
interface ToolExecutionResult<T> {
  success: boolean;
  data?: T;
  error?: {
    code: ErrorCode;
    message: string;
    retryable: boolean;
    suggestion?: string;
    details?: Record<string, unknown>;
  };
  metadata?: {
    latencyMs: number;
    source?: string;
    tokenCount?: number;
  };
}
```

|------|-------------|-----------|

| `UNAUTHORIZED` | Authentication failed or insufficient permissions | No |

| `NOT_FOUND` | Requested resource not found | No |
| `TIMEOUT` | Operation timed out | Yes |

| `INVALID_STATE` | Operation not valid in current state | No |

## Tool Registry

The `toolRegistry` singleton manages all registered tools and provides contextual access.

### Registration

```typescript
import { toolRegistry } from "@openplane/ai";

// Tools self-register via .register()
searchHybridTool.register();

// Or register manually
toolRegistry.register(metadata, coreTool, cacheKeyFn);
```

### Retrieving Tools

```typescript
// Single tool
const tool = toolRegistry.getTool("search_hybrid");

// All tools as Record<string, AISDKTool>
const allTools = toolRegistry.getAllTools();

// By category
const searchTools = toolRegistry.getByCategory("search");

// By multiple categories
const readTools = toolRegistry.getByCategoryTools(["search", "rag", "documents"]);

// Contextual (respecting permissions and deferred loading)
const tools = toolRegistry.getContextualTools(context);

// With explicit mask (loaded deferred tools, disabled tools)
const tools = toolRegistry.getToolsWithMask(context, {
  loaded: ["connector_sync"],
  disabled: ["doc_delete"],
});
```

### Context Management

Tools access execution context (team, user, permissions) through `AsyncLocalStorage`:

```typescript
// Run tools within a context
const result = await toolRegistry.runWithContextAsync(
  {
    teamId: "team_123",
    userId: "user_456",
    accessControl: ["group:engineering"],
    services: boundServices,
  },
  async () => {
    // Tools called here receive this context automatically
    return someToolExecution();
  }
);
```

### Tool Search

Find tools by keyword when you don't know the exact name:

```typescript
const results = await toolRegistry.search({
  query: "find documents",
  category: "search",
  limit: 5,
});
// Returns ToolMetadata[] ranked by relevance
```

### Multi-Execution

Execute multiple tools in parallel or sequentially:

```typescript
const result = await toolRegistry.multiExecute({
  tools: ["search_hybrid", "search_semantic"],
  inputs: [
    { query: "deployment guide", limit: 5 },
    { query: "deployment guide", limit: 5 },
  ],
  ctx: toolContext,
  parallel: true,
  maxConcurrency: 5,
});
// result.results: ToolExecutionResult[]
// result.totalLatencyMs: number
// result.parallelized: boolean
```

### Execution Callbacks

Monitor tool executions for observability:

```typescript
const unsubscribe = toolRegistry.onExecute((tool, params, result, durationMs) => {
  metrics.recordToolCall(tool.metadata.name, durationMs);
});
```

## Risk Profiles and Approval

Tools can declare their risk level. The approval pattern is auto-derived from `stakes` and `reversibility`:

| Stakes / Reversibility | Easy | Hard | Irreversible |
|------------------------|------|------|-------------|
| **Low** | `auto` | `quick-confirm` | `explicit` |
| **Medium** | `quick-confirm` | `suggest-apply` | `explicit` |
| **High** | `suggest-apply` | `explicit` | `explicit` |

```typescript
const deleteTool = defineTool({
  name: "doc_delete",
  description: "Delete a document permanently",
  category: "documents",
  stakes: "high",
  reversibility: "irreversible",
  // Auto-derives approval: "explicit"
  parameters: z.object({ documentId: z.string() }),
  execute: async (params, ctx) => { /* ... */ },
});
```

**Approval patterns:**

| Pattern | Behavior |
|---------|----------|
| `auto` | Executes without confirmation |
| `quick-confirm` | One-click confirmation dialog |
| `suggest-apply` | Shows plan, user approves or edits |
| `explicit` | Full review with detailed explanation |

## Permission Modes

Four permission modes control which tool categories are available:

| Mode | Allowed Categories | Can Write | Can Execute |
|------|-------------------|-----------|-------------|
| `default` | search, rag, documents, data, analysis | No | No |
| `readOnly` | search, rag, documents, data | No | No |
| `elevated` | All categories | Yes | Yes |
| `plan` | search, rag, documents, data, analysis | No | No |

## Deferred Loading

Tools marked with `deferLoading: true` are not loaded into the agent's tool set by default. This keeps the tool count manageable for the LLM. Agents discover and load deferred tools on demand:

```typescript
const specializedTool = defineTool({
  name: "connector_sync",
  deferLoading: true,
  searchKeywords: ["sync", "refresh", "update"],
  // ...
});
```

## Creating Custom Tools

To add a new tool:

1. Create the file in `packages/ai/src/tools/definitions/{category}/`
2. Define the tool with `defineTool()`
3. Export and re-export from the category's `index.ts`
4. Call `.register()` at module load time

```typescript
// packages/ai/src/tools/definitions/search/my-tool.ts
import { defineTool, success, z } from "../../builder";

export const mySearchTool = defineTool({
  name: "search_custom",
  description: "Custom search with special ranking",
  category: "search",
  parameters: z.object({
    query: z.string().describe("Search query"),
  }),
  async execute(params, ctx) {
    const results = await ctx.services.search.custom(params.query, ctx.teamId);
    return success(results);
  },
});

mySearchTool.register();
```

The tool is immediately available to agents and MCP clients after registration.
