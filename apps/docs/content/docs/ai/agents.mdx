# Agent Patterns

Agents orchestrate LLM calls, tool invocations, and sub-agent delegation into coherent workflows. OpenBeam provides six composable patterns that can be nested arbitrarily.

## Core Interface

Every agent implements `ExecutableAgent`:

```typescript
interface ExecutableAgent {
  readonly config: AgentConfig;
  execute(input: unknown, ctx: AgentExecutionContext): Promise<AgentExecutionResult>;
  stream?(input: unknown, ctx: AgentExecutionContext): AsyncGenerator<AgentStreamChunk>;
}
```

### Execution Context

The context carries identity, state, memory, and control signals:

```typescript
interface AgentExecutionContext {
  teamId: string;
  userId: string;
  sessionId?: string;
  state: AgentState;                         // Shared key-value state
  memory?: MemoryAccess;                     // Learned facts, corrections
  abortSignal?: AbortSignal;                 // Cancellation
  parentTrace?: ExecutionTrace;              // Trace tree
  accessControl?: string[];                  // Permission IDs
  conversationHistory?: ConversationMessage[];
  canvasState?: CanvasStateSnapshot;
  metadata?: Record<string, unknown>;
}
```

### Execution Result

Every execution returns output, updated state, a full trace tree, token counts, and duration:

```typescript
interface AgentExecutionResult {
  output: unknown;
  state: AgentState;
  trace: ExecutionTrace;
  finishReason: FinishReason;
  totalTokens: { inputTokens: number; outputTokens: number };
  durationMs: number;
}
```

## Agent State

Agents share data through `AgentState` -- a key-value map with full history tracking. Each agent reads from `inputRefs` and writes to `outputKey`.

```typescript
import { createEmptyState } from "@openbeam/ai";

const state = createEmptyState();
// state.values: Map<string, unknown>    -- current values
// state.history: AgentStateSnapshot[]   -- full audit trail
```

Sub-agents in Sequential or Parallel patterns automatically pass outputs through state. No manual wiring needed.

## Pattern Reference

### LLM Agent

Single LLM call with tool access. The workhorse pattern for most tasks. Implements the ReAct loop: think, act (call tool), observe (read result), repeat.

**When to use:** Single-turn tasks, tool-augmented Q&A, search, document analysis.

```typescript
import { createLlmAgent } from "@openbeam/ai";

const researchAgent = createLlmAgent({
  type: "llm",
  name: "research",
  description: "Research agent with search capabilities",
  systemPrompt: `You are a research assistant. Search for information,
    read documents, and provide grounded answers with citations.`,
  tools: ["search_hybrid", "doc_get", "rag_answer"],
  maxSteps: 10,
  model: {
    providerId: "anthropic",
    modelId: "claude-sonnet-4-20250514",
    temperature: 0.3,
    thinking: { enabled: true, thinkingLevel: "medium" },
  },
});

const result = await researchAgent.execute(
  "What is our current deployment process?",
  { teamId: "team_1", userId: "user_1", state: createEmptyState() }
);
```

**Config:**

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `tools` | `string[]` | `undefined` | Tool names from registry. `["*"]` for all tools. |
| `maxSteps` | `number` | `10` | Max tool-call rounds before stopping |
| `systemPrompt` | `string` | `undefined` | System prompt for the LLM |
| `model.providerId` | `ProviderId` | Auto-detected | `"anthropic"`, `"openai"`, `"google"` |
| `model.temperature` | `number` | Provider default | Sampling temperature |
| `model.thinking` | `ThinkingConfig` | Disabled | Extended thinking / chain-of-thought |

### Sequential Agent

Pipeline execution: A's output becomes B's input, then B's output becomes C's input. Each sub-agent runs to completion before the next begins.

**When to use:** Multi-step pipelines, research-then-synthesize, extract-transform-load.

```typescript
import { createSequentialAgent, createLlmAgent } from "@openbeam/ai";

const pipeline = createSequentialAgent({
  type: "sequential",
  name: "research-pipeline",
  subAgents: [
    {
      type: "llm",
      name: "search",
      tools: ["search_hybrid"],
      systemPrompt: "Search for documents about the user's topic. Return raw results.",
      maxSteps: 5,
    },
    {
      type: "llm",
      name: "analyze",
      tools: ["doc_get", "doc_chunks"],
      systemPrompt: "Read and analyze the documents from the search results.",
      maxSteps: 5,
    },
    {
      type: "llm",
      name: "synthesize",
      systemPrompt: "Synthesize the analysis into a clear, cited answer.",
      maxSteps: 1,
    },
  ],
});
```

**Data flow:** `input → search → analyze → synthesize → output`

---

### Parallel Agent

Concurrent execution of sub-agents on the same input. Results are aggregated using a configurable strategy.

**When to use:** Multiple independent analyses, fan-out queries, multi-source research.

```typescript
import { createParallelAgent } from "@openbeam/ai";

const multiSourceResearch = createParallelAgent({
  type: "parallel",
  name: "multi-source",
  subAgents: [
    { type: "llm", name: "slack-search", tools: ["search_hybrid"],
      systemPrompt: "Search Slack for relevant discussions." },
    { type: "llm", name: "docs-search", tools: ["search_hybrid"],
      systemPrompt: "Search documentation for relevant pages." },
    { type: "llm", name: "code-search", tools: ["search_hybrid"],
      systemPrompt: "Search code repositories for implementations." },
  ],
  aggregator: { strategy: "merge" },
});
```

**Aggregation strategies:**

| Strategy | Behavior |
|----------|----------|
| `merge` | Each sub-agent's output stored under its `outputKey` or `name` |
| `concat` | String outputs joined with `\n\n---\n\n` separators |
| `first` | Returns only the first sub-agent's output |
| `custom` | Returns the raw output array for custom processing |

---

### Coordinator Agent

Routes input to the most appropriate sub-agent based on condition matching. Acts as a dispatcher.

**When to use:** Multi-domain assistants, intent-based routing, tiered processing.

```typescript
import { createCoordinatorAgent } from "@openbeam/ai";

const router = createCoordinatorAgent({
  type: "coordinator",
  name: "query-router",
  subAgents: [
    {
      type: "llm", name: "code-agent",
      matchCondition: "contains:code",
      tools: ["search_hybrid"], systemPrompt: "Help with code questions.",
    },
    {
      type: "llm", name: "hr-agent",
      matchCondition: "contains:policy",
      tools: ["search_hybrid"], systemPrompt: "Help with HR policy questions.",
    },
    {
      type: "llm", name: "general-agent",
      tools: ["search_hybrid"], systemPrompt: "General assistant.",
    },
  ],
  defaultAgent: "general-agent",
});
```

**Match conditions:**

| Syntax | Example | Behavior |
|--------|---------|----------|
| `contains:term` | `contains:code` | Input includes the term |
| `startsWith:prefix` | `startsWith:help` | Input starts with the prefix |
| `matches:regex` | `matches:^(bug\|error)` | Input matches the regex |
| `type:value` | `type:code_review` | Input object has `{type: "code_review"}` |

---

### Loop Agent

Iterates sub-agents until a stop condition is met or max iterations reached.

**When to use:** Iterative refinement, polling, convergence-based workflows.

```typescript
import { createLoopAgent } from "@openbeam/ai";

const iterativeResearch = createLoopAgent({
  type: "loop",
  name: "deep-research",
  subAgents: [
    {
      type: "llm", name: "researcher",
      tools: ["search_hybrid", "doc_get"],
      systemPrompt: "Research the topic. Set done=true when you have comprehensive coverage.",
    },
  ],
  maxIterations: 5,
  stopCondition: {
    type: "expression",
    expression: "output.done === true",
  },
});
```

**Stop conditions:**

| Type | Config | Stops When |
|------|--------|------------|
| `expression` | `expression: "output.done === true"` | Output object has `{done: true}` |
| `expression` | `expression: "output.quality >= 0.8"` | Quality score threshold met |
| `expression` | `expression: "iteration >= 3"` | Fixed iteration count |
| `tool` | `toolName: "finish"` | Agent calls the named tool |

Default max iterations: 10.

---

### Generator-Critic Agent

Generate-then-critique loop. A generator agent produces output, a critic agent evaluates it. If the critique fails, the generator receives feedback and tries again.

**When to use:** Quality-gated content, self-improving outputs, review workflows.

```typescript
import { createGeneratorCriticAgent } from "@openbeam/ai";

const writer = createGeneratorCriticAgent({
  name: "document-writer",
  generator: {
    type: "llm",
    name: "writer",
    systemPrompt: "Write a clear, well-structured document based on the input.",
    maxSteps: 1,
  },
  critic: {
    type: "llm",
    name: "reviewer",
    systemPrompt: `Review the document for accuracy, clarity, and completeness.
      Return JSON: { "passed": boolean, "score": 0-1, "feedback": "..." }`,
    maxSteps: 1,
  },
  maxIterations: 3,
  qualityThreshold: 0.8,
});

const result = await writer.execute("Write onboarding documentation for new engineers", ctx);
// result.output = { draft, critique, iterations, passed }
```

**Output shape:**

```typescript
interface GeneratorCriticOutput {
  draft: unknown;        // Final generated content
  critique: {
    passed: boolean;     // Whether quality gate was met
    score?: number;      // 0-1 quality score
    feedback?: string;   // Critique feedback
  };
  iterations: number;    // How many rounds ran
  passed: boolean;       // Whether the final output passed
}
```

The critic can return its verdict as:
- A string: `"PASS"` or `"PASS: looks good"` to pass, anything else is feedback
- An object with `{ passed: boolean, score?, feedback? }`
- An object with `{ score: number }` (compared against `qualityThreshold`)
- An object with `{ verdict: "PASS" | "FAIL" }`

## Streaming

All patterns support streaming via the `stream()` method. Stream chunks carry type information for progressive UI rendering.

```typescript
for await (const chunk of agent.stream(input, ctx)) {
  switch (chunk.type) {
    case "text":
      process.stdout.write(chunk.content);
      break;
    case "thinking":
      console.log(`[thinking] ${chunk.content}`);
      break;
    case "tool-call":
      console.log(`Calling ${chunk.toolName}...`);
      break;
    case "tool-result":
      console.log(`${chunk.toolName} returned`);
      break;
    case "step":
      console.log(`Step: ${chunk.content}`);
      break;
    case "done":
      console.log(`Finished in ${chunk.result.durationMs}ms`);
      break;
  }
}
```

**Stream chunk types:**

| Type | Fields | Description |
|------|--------|-------------|
| `text` | `content` | Text delta from the LLM |
| `thinking` | `content` | Extended thinking / reasoning content |
| `tool-call` | `toolName`, `toolInput`, `toolCallId` | Agent is invoking a tool |
| `tool-result` | `toolName`, `toolOutput`, `toolCallId` | Tool returned a result |
| `step` | `content`, `step` | Sub-agent completed a step |
| `done` | `result` | Agent finished, full result available |

For composite agents (Sequential, Parallel), chunk `agentName` is prefixed with the parent: `"pipeline/search"`, `"multi-source/slack-search"`. Loop agents include the iteration: `"deep-research[2]/researcher"`.

## Extended Thinking

LLM agents support extended thinking for complex reasoning tasks. Configure per-provider:

```typescript
const agent = createLlmAgent({
  type: "llm",
  name: "analyst",
  model: {
    providerId: "anthropic",
    modelId: "claude-sonnet-4-20250514",
    thinking: {
      enabled: true,
      thinkingLevel: "high",    // "minimal" | "low" | "medium" | "high"
      includeThoughts: true,    // Include reasoning in stream chunks
    },
  },
  tools: ["search_hybrid"],
  maxSteps: 10,
});
```

Thinking budget by provider and level:

| Level | Anthropic (tokens) | OpenAI (effort) | Google Gemini 2.5 (tokens) |
|-------|--------------------|-----------------|---------------------------|
| `minimal` | 2,048 | low | 1,024 |
| `low` | 4,096 | low | 4,096 |
| `medium` | 8,192 | medium | 8,192 |
| `high` | 16,384 | high | 16,384 |

## Execution Traces

Every agent execution produces a trace tree. Traces capture timing, token usage, tool calls, and status for observability.

```typescript
interface ExecutionTrace {
  agentName: string;
  type: AgentType;
  startTime: number;
  endTime?: number;
  status: "running" | "completed" | "failed" | "skipped";
  input?: unknown;
  output?: unknown;
  error?: string;
  children: ExecutionTrace[];   // Sub-agent traces
  tokenUsage?: { inputTokens: number; outputTokens: number };
  toolCalls?: ToolCallRecord[];
}
```

For a Sequential agent running three sub-agents, the trace tree looks like:

```text
research-pipeline (sequential)
├── search (llm) - 2 tool calls, 1.2s
├── analyze (llm) - 3 tool calls, 2.4s
└── synthesize (llm) - 0 tool calls, 0.8s
```

## Pattern Selection Guide

| Pattern | Input | Output | Use When |
|---------|-------|--------|----------|
| **LLM** | Query | Answer | Single-turn tasks with optional tool use |
| **Sequential** | Query | Refined answer | Multi-step pipeline (search, analyze, synthesize) |
| **Parallel** | Query | Aggregated answers | Independent analyses of the same input |
| **Coordinator** | Query | Routed answer | Multi-domain routing by intent |
| **Loop** | Query | Converged answer | Iterative refinement until quality threshold |
| **Generator-Critic** | Spec | Quality-gated output | Self-reviewing content generation |
