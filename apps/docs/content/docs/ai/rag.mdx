# RAG Pipeline

The RAG pipeline grounds LLM answers in source documents. It analyzes the query, reranks retrieved chunks, generates answers with citations, and verifies every factual claim against the source material.

## Pipeline Stages

```text
Query → Analyze → Rerank → Build Context → Generate → Ground → Respond
```

| Stage | What Happens | Latency |
|-------|-------------|---------|
| **Analyze** | Classify intent, extract entities, detect temporal context | < 5ms |
| **Rerank** | Score and reorder chunks by relevance to the analyzed query | < 10ms |
| **Build Context** | Assemble prompt with citation map and token budget | < 5ms |
| **Generate** | Stream answer from LLM with inline citations | 500-3000ms |
| **Ground** | Verify each claim against source chunks, compute confidence | < 20ms |

## Quick Start

```typescript
import { answerWithRAG, streamRAGAnswer } from "@openplane/ai";
import type { RAGChunk } from "@openplane/types/ai";

// Chunks from search results
const chunks: RAGChunk[] = [
  {
    id: "chunk_1",
    content: "Our API rate limit is 100 requests per minute per API key.",
    documentId: "doc_api_docs",
    documentTitle: "API Documentation",
    documentUrl: "https://docs.example.com/api",
    score: 0.92,
  },
  {
    id: "chunk_2",
    content: "Rate limiting uses a sliding window algorithm with per-key tracking.",
    documentId: "doc_architecture",
    documentTitle: "Architecture Guide",
    documentUrl: "https://docs.example.com/arch",
    score: 0.85,
  },
];

// One-shot answer
const response = await answerWithRAG("What is our API rate limit?", chunks);
console.log(response.answer);      // "The API rate limit is 100 requests..."
console.log(response.citations);   // [{documentId, chunkId, text, relevanceScore}]
console.log(response.confidence);  // "high"
console.log(response.grounding);   // {overallScore: 0.95, claims: [...]}

// Streaming answer
for await (const event of streamRAGAnswer("What is our API rate limit?", chunks)) {
  switch (event.type) {
    case "analysis":  console.log("Query analyzed:", event.analysis.intent); break;
    case "text":      process.stdout.write(event.content); break;
    case "citation":  console.log("Citation:", event.citation); break;
    case "grounding": console.log("Grounding warning:", event.grounding); break;
    case "done":      console.log("Tokens used:", event.usage); break;
  }
}
```

## RAGEngine Configuration

```typescript
import { RAGEngine } from "@openplane/ai";

const engine = new RAGEngine({
  providerId: "anthropic",
  modelId: "claude-sonnet-4-20250514",
  temperature: 0.3,
  enableGrounding: true,
  groundingThreshold: 0.3,
  rerankingOptions: {
    maxChunks: 10,
    minScore: 0.1,
  },
});

// Create a variant with different config
const fastEngine = engine.withConfig({ temperature: 0.1 });
```

| Config | Type | Default | Description |
|--------|------|---------|-------------|
| `providerId` | `ProviderId` | Auto-detected | LLM provider |
| `modelId` | `string` | Default chat model | Model to use for generation |
| `temperature` | `number` | `0.3` | Low temperature for factual accuracy |
| `enableGrounding` | `boolean` | `true` | Enable claim verification |
| `groundingThreshold` | `number` | `0.3` | Minimum overlap score for a claim to be "supported" |
| `rerankingOptions` | `object` | `{}` | Chunk reranking parameters |

## Query Analyzer

The query analyzer classifies intent, extracts entities, detects temporal context, and decomposes complex queries -- all without an LLM call. It runs in under 5ms using pattern matching and heuristics.

```typescript
import { analyzeQuery } from "@openplane/ai";

const analysis = analyzeQuery("What did John work on last quarter?");
```

**Output:**

```typescript
interface QueryAnalysis {
  originalQuery: string;
  normalizedQuery: string;
  intent: QueryIntent;         // "question" | "definition" | "comparison" | "howto" | ...
  subQueries: string[];        // Decomposed sub-queries
  entities: ExtractedEntity[]; // People, products, technologies, dates
  temporalContext: TemporalContext | null;  // Date ranges from "last quarter", etc.
  requiresContext: boolean;    // Needs conversation history
  confidence: number;          // 0-1 analysis confidence
  keywords: string[];          // Key terms minus stopwords
}
```

### Intent Classification

| Intent | Triggers | Example |
|--------|----------|---------|
| `question` | Starts with what/why/how/when/where/who, or ends with `?` | "What is our deployment process?" |
| `definition` | "what is", "define", "meaning of" | "What is a service mesh?" |
| `comparison` | "compare", "vs", "difference between" | "Kubernetes vs Docker" |
| `howto` | "how to", "steps to", "guide to" | "How to set up CI/CD" |
| `command` | "show me", "find", "list", "get" | "Show me recent PRs" |
| `search` | No question pattern detected | "Q3 revenue report" |
| `followup` | Contains pronouns referencing conversation context | "Tell me more about it" |
| `clarification` | "I meant", "actually", "to clarify" | "I meant the staging deployment" |

### Entity Extraction

Entities are extracted using pattern matching against known categories:

| Entity Type | Examples |
|-------------|---------|
| `person` | `@alice`, proper names |
| `technology` | kubernetes, react, typescript, postgresql, redis |
| `product` | github, slack, notion, linear, jira |
| `organization` | google, anthropic, stripe, cloudflare |
| `date` | Q3 2024, January 2025 |

### Temporal Context Detection

The analyzer extracts date ranges from natural language:

| Pattern | Extracted Range |
|---------|----------------|
| "last 3 days" | 3 days ago → now |
| "this quarter" | Quarter start → now |
| "yesterday" | Yesterday → yesterday |
| "since January 2025" | Jan 1, 2025 → now |
| "before March 2025" | Beginning → Mar 1, 2025 |

### Conversation Context

For multi-turn conversations, the analyzer resolves pronouns and detects topic shifts:

```typescript
import { buildConversationContext, enrichQueryWithContext } from "@openplane/ai";

const conversationCtx = buildConversationContext("conv_123", turns);
const analysis = analyzeQuery("Tell me more about it", conversationCtx);
const enrichedQuery = enrichQueryWithContext(analysis, conversationCtx);
// Pronouns replaced with entities from conversation history
```

## Grounding Verification

After the LLM generates an answer, the grounding system verifies every factual claim against the source chunks.

```typescript
import { verifyGrounding } from "@openplane/ai";

const grounding = verifyGrounding(answer, chunks, threshold);
```

**How it works:**

1. **Extract claims** -- Sentences containing factual patterns (verbs like "is", "provides", "requires") are identified as claims. Questions, opinions ("I think"), and instructions ("you should") are filtered out.

2. **Build chunk index** -- Source chunks are tokenized into a term-to-chunk inverted index with bigram support for phrase matching.

3. **Verify each claim** -- Each claim's significant terms are matched against the chunk index. An overlap score (0-1) measures how well the claim is supported.

4. **Compute confidence** -- Overall confidence derived from the proportion of supported claims and their individual confidence scores.

**Grounding result:**

```typescript
interface GroundingResult {
  claims: ClaimVerification[];   // Per-claim verification
  overallScore: number;          // 0-1 proportion of supported claims
  confidence: GroundingConfidence; // "high" | "medium" | "low" | "uncertain"
  unsupportedClaims: string[];   // Claims without evidence
}

interface ClaimVerification {
  claim: string;
  supported: boolean;
  evidenceChunkId: string | null;
  evidenceSnippet: string | null;
  confidence: number;           // 0-1
}
```

**Confidence thresholds:**

| Confidence | Overall Score | Avg Claim Confidence |
|------------|--------------|---------------------|
| `high` | >= 0.8 | >= 0.6 |
| `medium` | >= 0.5 | >= 0.4 |
| `low` | >= 0.3 | Any |
| `uncertain` | < 0.3 | Any |

### Refusal Handling

When grounding is too weak, the system can refuse to answer rather than hallucinate:

```typescript
import { checkForRefusal } from "@openplane/ai";

const refusal = checkForRefusal(groundingResult, chunks);
if (refusal) {
  // refusal.type: "noSources" | "lowConfidence" | "mixedGrounding" | "outOfScope"
  // refusal.message: User-facing explanation
  // refusal.suggestedAction: What the user should try instead
}
```

## Streaming Events

The streaming API emits typed events for progressive UI rendering:

| Event Type | Fields | When |
|------------|--------|------|
| `analysis` | `analysis: QueryAnalysis` | Query analyzed |
| `retrieval` | (none) | Chunks reranked |
| `context` | (none) | Prompt context built |
| `text` | `content: string` | LLM text delta |
| `citation` | `citation: Citation` | Citation extracted from text |
| `grounding` | `grounding: GroundingResult` | Grounding warning (only if issues found) |
| `done` | `usage: RAGTokenUsage` | Generation complete |

**Token usage:**

```typescript
interface RAGTokenUsage {
  promptTokens: number;
  completionTokens: number;
  totalTokens: number;
}
```

## Prompt Templates

The RAG system uses XML-structured prompts for clear instruction boundaries.

### System Prompt

```xml
<instructions>
You are an enterprise search assistant. Answer questions using ONLY the provided
context documents.

<rules>
1. Answer from context only. If information is insufficient, say so clearly
2. Cite sources using [N] notation where N corresponds to the document number
3. Be concise and direct. Prefer bullet points for lists
4. Never fabricate information not present in the context
5. If asked about something outside the context, acknowledge the limitation
6. When uncertain, express your confidence level
</rules>
</instructions>

<output_format>
<answer>Your response here, with inline citations [1], [2], etc.</answer>
<confidence>high|medium|low</confidence>
</output_format>
```

### Context Injection

Source chunks are formatted with numbered references:

```text
[1] API Documentation
Our API rate limit is 100 requests per minute per API key.

[2] Architecture Guide
Rate limiting uses a sliding window algorithm with per-key tracking.
```

The citation map tracks `[N]` references back to source documents for extraction from the LLM's response.

## RAG Response Shape

```typescript
interface RAGResponse {
  answer: string;                    // Generated answer with [N] citations
  citations: Citation[];             // Extracted citation references
  grounding: GroundingResult | null; // Claim verification results
  usage: RAGTokenUsage;              // Token counts
  timing: RAGTiming;                 // Per-stage latency breakdown
  confidence: GroundingConfidence;   // Overall confidence
  followUpQuestions: string[];       // Suggested follow-up questions
}

interface RAGTiming {
  analysisMs: number;
  retrievalMs: number;
  rerankingMs: number;
  generationMs: number;
  groundingMs: number;
  totalMs: number;
  firstTokenMs: number | null;     // Time to first token (streaming)
}
```

## Agent Tools

The RAG pipeline is exposed as agent tools:

| Tool | Description |
|------|-------------|
| `rag_answer` | Generate a grounded answer with citations |
| `rag_analyze` | Analyze a query without generating an answer |
| `rag_verify` | Verify claims in existing text against source chunks |
| `rag_synthesize` | Synthesize information from multiple sources |

These tools are used internally by the LLM agent when answering questions, and can be composed into larger workflows via Sequential or Parallel agents.
