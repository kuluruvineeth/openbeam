# Testing

## Running Tests

```bash
bun test apps/bot/__tests__/

bun test apps/bot/__tests__/renderers/slack.test.ts

bun test --watch apps/bot/__tests__/
```

## Test Structure

```
apps/bot/__tests__/
├── adapters/
│   ├── slack.test.ts           # HMAC verification, event parsing
│   ├── discord.test.ts         # Ed25519 + interaction parsing
│   ├── telegram.test.ts        # Secret token + update parsing
│   └── whatsapp.test.ts        # HMAC-SHA256 + webhook payload parsing
├── renderers/
│   ├── slack.test.ts           # Block Kit output for all response types
│   ├── discord.test.ts         # Embed colors, fields, components
│   ├── telegram.test.ts        # HTML formatting + inline keyboards
│   ├── teams.test.ts           # Adaptive Card structure + FactSet citations
│   └── whatsapp.test.ts        # Interactive payloads + typing indicator format
├── handlers/
│   └── router.test.ts          # Command dispatch, intent detection, greetings
├── identity/
│   ├── resolver.test.ts        # BotUserLink lookup
│   └── linking.test.ts         # Magic link token generation
└── lib/
    └── rate-limit.test.ts      # Per-user + per-team rate limiting with retry timing
```

## Writing New Tests

### Mocking Services

The router tests mock `@openbeam/services` and `@openbeam/db` to avoid hitting real databases:

```typescript
mock.module("@openbeam/services", () => ({
  hybridSearch: () => Promise.resolve({ documents: [], total: 0, queryTime: 0 }),
  ragAnswer: () => Promise.resolve({
    answer: "test answer",
    citations: [],
    context: { documents: [] },
    usage: { promptTokens: 0, completionTokens: 0, totalTokens: 0 },
  }),
  dispatchAction: () => Promise.resolve({ success: true, data: {} }),
}));
```

### Testing Renderers

Renderer tests are pure functions — no mocks needed:

```typescript
import { renderSlack } from "../../src/renderers/slack";

const payload = renderSlack({
  type: "answer",
  text: "Deploy uses GitHub Actions.",
  citations: [{ index: 1, title: "Guide", url: "https://x.co/1" }],
  followUps: ["Tell me more", "Search for deploy"],
});

expect(payload.blocks.some((b) => b.type === "context")).toBe(true);
expect(payload.blocks.some((b) => b.type === "actions")).toBe(true);
```

### Testing Adapters

Adapter tests should mock the platform SDK and verify:

1. Signature verification accepts valid / rejects invalid signatures
2. Event parsing produces correct `UnifiedMessage` fields
3. Response sending calls the right platform API with the renderer's output
