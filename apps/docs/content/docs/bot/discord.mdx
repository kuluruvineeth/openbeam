# Discord Setup

Discord uses HTTP-based interactions (no WebSocket gateway required). The bot receives slash commands via webhook and responds with rich embeds.

## Prerequisites

- A Discord account with a server where you have admin permissions
- OpenBeam bot running locally or deployed (see [Quickstart](/docs/bot/quickstart))

## Step 1: Create a Discord Application

1. Go to [discord.com/developers/applications](https://discord.com/developers/applications)
2. Click **New Application** and name it "OpenBeam"
3. Note the **Application ID** and **Public Key** from the General Information page

## Step 2: Create a Bot User

1. Go to the **Bot** section in your application
2. Click **Reset Token** (or **Add Bot** if first time)
3. Copy the **Bot Token** — you won't be able to see it again

<Callout type="warn">
Never commit the bot token to source control. If it's leaked, reset it immediately in the Discord Developer Portal.
</Callout>

## Step 3: Configure Interactions Endpoint

1. Go to **General Information**
2. Set **Interactions Endpoint URL** to:

```
https://your-domain.com/webhooks/discord
```

3. Click **Save Changes**

Discord sends a PING interaction to verify the endpoint. The bot responds with `{ type: 1 }` automatically. If verification fails, check that the bot is running and the URL is accessible.

## Step 4: Configure Environment

```bash
DISCORD_APPLICATION_ID=your-application-id
DISCORD_PUBLIC_KEY=your-public-key
DISCORD_BOT_TOKEN=your-bot-token
```

| Credential | Where to Find |
|------------|--------------|
| **Application ID** | General Information > Application ID |
| **Public Key** | General Information > Public Key |
| **Bot Token** | Bot > Token (click Reset Token to reveal) |

## Step 5: Register Slash Commands

Register the bot's slash commands with Discord's API:

```bash
DISCORD_BOT_TOKEN=... DISCORD_APPLICATION_ID=... bun run apps/bot/scripts/register-discord-commands.ts
```

This registers the following global slash commands:

| Command | Description |
|---------|-------------|
| `/search <query>` | Search across connected data sources |
| `/ask <question>` | Ask a question with AI-powered answers |
| `/expert <topic>` | Find topic experts |
| `/link` | Link your Discord account to OpenBeam |

<Callout type="info">
**Global commands take up to 1 hour to propagate.** For instant testing during development, register as guild-specific commands instead by passing a `guild_id` parameter. Guild commands are available immediately.
</Callout>

## Step 6: Invite the Bot to Your Server

Construct the invite URL with the necessary scopes:

```
https://discord.com/api/oauth2/authorize?client_id=YOUR_APPLICATION_ID&scope=applications.commands+bot
```

Replace `YOUR_APPLICATION_ID` with your Application ID and open the URL in your browser. Select the server and click **Authorize**.

## Step 7: Test

In your Discord server, type:

```
/search deployment runbook
```

The bot responds with a color-coded embed (blue for search results) with follow-up component buttons.

## Features

| Feature | Status |
|---------|--------|
| Slash commands | Supported — `/search`, `/ask`, `/expert`, `/link` |
| Rich embeds | Supported — color-coded by response type |
| Component buttons | Supported — follow-up suggestions |
| Semantic colors | Blue (info), Green (success), Red (error), Gray (muted) |
| Ephemeral messages | Not yet implemented |
| Thread creation | Not yet implemented |
| Deferred replies | Not yet implemented (3-second timeout applies) |
| Account linking | Magic link via `/link` command |

## Response Format

The Discord adapter produces embed objects with component action rows:

- **Search results**: Blue embed with title, description (numbered results with links), footer
- **AI answers**: Blue embed with answer text, footer with citation references
- **Expert list**: Blue embed with inline fields (name + expertise per expert)
- **Action results**: Green (success) or Red (error) embed
- **Follow-ups**: Component row with secondary-style buttons

## How It Works

The Discord adapter uses HTTP interactions (no WebSocket gateway):

- **Signature verification**: Ed25519 via `discord-interactions` `verifyKey()`
- **PING handling**: Responds with `{ type: 1 }` for endpoint verification
- **Event parsing**: Zod schemas validate interaction payloads
- **Response rendering**: `renderDiscord()` produces embed + component payload
- **Message sending**: POST to `https://discord.com/api/v10/interactions/{id}/{token}/callback`
