# MCP Server

OpenBeam ships an MCP server that gives AI assistants access to your enterprise knowledge — 103+ connectors, hybrid search, RAG answers, and agent execution.

## Quick Setup

### Claude Desktop (Recommended)

Open **Settings > Connectors** in Claude Desktop, then add OpenBeam as a remote MCP server:

```
URL: https://mcp.openbeam.work/mcp
```

Claude will prompt you to authenticate with your OpenBeam account via OAuth.

Alternatively, add to `~/Library/Application Support/Claude/claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "openbeam": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://mcp.openbeam.work/mcp"]
    }
  }
}
```

<Callout type="info">
  This connects to the hosted OpenBeam API. You only need an OpenBeam account — no database URLs, no infrastructure setup.
</Callout>

### Claude Code

```bash
claude mcp add --transport http openbeam https://mcp.openbeam.work/mcp
```

Then run `/mcp` in a Claude Code session to authenticate.

### Cursor

Add to `.cursor/mcp.json` in your project root:

```json
{
  "mcpServers": {
    "openbeam": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://mcp.openbeam.work/mcp"]
    }
  }
}
```

### Windsurf / Codex / Any MCP Host

Use the remote MCP URL directly if the host supports HTTP transport:

```
https://mcp.openbeam.work/mcp
```

Or use `mcp-remote` for stdio-based hosts:

```bash
npx -y mcp-remote https://mcp.openbeam.work/mcp
```

## Self-Hosted Setup

If you run your own OpenBeam instance, use the local MCP server with an API key:

```json
{
  "mcpServers": {
    "openbeam": {
      "command": "npx",
      "args": ["-y", "@openbeam/mcp-server"],
      "env": {
        "MCP_API_KEY": "your-api-key",
        "OPENBEAM_URL": "https://your-instance.example.com"
      }
    }
  }
}
```

| Variable | Required | Description |
|----------|----------|-------------|
| `MCP_API_KEY` | Yes | API key from your OpenBeam Settings |
| `OPENBEAM_URL` | Yes | Your self-hosted OpenBeam URL |

## Available Tools

Once connected, your AI assistant can use these tools:

### Search

| Tool | Description |
|------|-------------|
| `search_documents` | Hybrid semantic + keyword search across all connected sources |
| `search_people` | Find experts by name, email, department, or expertise |
| `get_document` | Retrieve full document content by ID |
| `get_related` | Find related documents by similarity or knowledge graph |

### Knowledge

| Tool | Description |
|------|-------------|
| `ask_question` | RAG-powered Q&A with citations from enterprise data |
| `list_connectors` | List all connected data sources and their sync status |
| `get_connector_stats` | Get detailed statistics for a connector |

### Agents

| Tool | Description |
|------|-------------|
| `run_agent` | Start an autonomous research or analysis agent |
| `deep_research` | Multi-step research across all enterprise sources |
| `get_job_status` | Check progress of async agent jobs |

## Resources

The server exposes enterprise data as browsable MCP resources:

| URI Pattern | Description |
|-------------|-------------|
| `openbeam://resources/{teamId}/` | Synced enterprise documents |
| `openbeam://user/{teamId}/{userId}/memories/` | User knowledge and preferences |
| `openbeam://agent/{teamId}/{agentId}/skills/` | Agent capabilities |
| `openbeam://tools/{teamId}/` | Tool definitions and stats |

## Verify It Works

After setup, ask your AI assistant:

> "What connectors are connected to OpenBeam?"

The assistant will call `list_connectors` and show your connected data sources.

> "Search for our authentication architecture docs"

The assistant will call `search_documents` and return results from Confluence, Notion, Google Drive, or wherever your docs live.

## Troubleshooting

| Issue | Fix |
|-------|-----|
| "Server not found" | Ensure Node.js 18+ is installed: `node --version` |
| "Authentication failed" | Re-authenticate via OAuth or check your API key |
| "No results" | Check that connectors are synced in the OpenBeam dashboard |
| Connection timeout | Verify `https://mcp.openbeam.work` is reachable |
