# Get running in 5 minutes

Clone the repo, start the infrastructure, and run your first search query.

## Prerequisites

| Tool | Version | Check |
|------|---------|-------|
| **Bun** | 1.3.2+ | `bun --version` |
| **Docker** | 24+ | `docker --version` |
| **Docker Compose** | v2+ | `docker compose version` |
| **Git** | 2.x | `git --version` |

<Callout type="info">
  Python 3.12+ and Go 1.24+ are only needed if you plan to work on the ML engine or CLI. The core platform runs entirely on Bun and Docker.
</Callout>

## Step 1: Clone and install

```bash
git clone https://github.com/kuluruvineeth/openplane.git
cd openplane
bun install
```

## Step 2: Start infrastructure

Start PostgreSQL, Redis, Vespa, and Temporal with the provided Docker Compose file:

```bash
docker compose -f scripts/deploy/infra-hetzner-compose.yaml up -d
```

Wait for all services to become healthy:

```bash
docker compose -f scripts/deploy/infra-hetzner-compose.yaml ps
```

Every service should show `healthy` status. Vespa takes the longest (up to 2 minutes on first start).

## Step 3: Configure environment

Create a `.env` file in the project root:

```bash title=".env"
# Database
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/openplane

# Redis
REDIS_URL=redis://localhost:6379

# Search
VESPA_URL=http://localhost:8280

# Temporal
TEMPORAL_ADDRESS=localhost:7233

# Auth
BETTER_AUTH_SECRET=generate-a-32-char-secret-here
BETTER_AUTH_URL=http://localhost:3000
JWT_SECRET=generate-another-secret-here

# Encryption (for connector credentials)
ENCRYPTION_KEY=generate-a-32-byte-hex-key

# AI (at least one required for AI features)
OPENAI_API_KEY=sk-...
# ANTHROPIC_API_KEY=sk-ant-...
# GOOGLE_AI_API_KEY=...

# Google OAuth (for Gmail, Drive, Calendar connectors)
GOOGLE_CLIENT_ID=your-client-id
GOOGLE_CLIENT_SECRET=your-client-secret

# Frontend
NEXT_PUBLIC_WEB_URL=http://localhost:3001
NEXT_PUBLIC_SERVER_URL=http://localhost:3000
CORS_ORIGIN=http://localhost:3001
COOKIE_DOMAIN=localhost
```

<Callout type="warn">
  AI features require at least one LLM API key. Search and sync work without one, but answers and agents need a configured provider.
</Callout>

## Step 4: Set up the database

Push the Prisma schema to PostgreSQL:

```bash
bun run db:push
```

## Step 5: Start all services

```bash
bun run dev
```

This starts:

| Service | URL | Purpose |
|---------|-----|---------|
| **Web** | http://localhost:3001 | Frontend application |
| **Server** | http://localhost:3000 | API server |
| **Worker** | (background) | Temporal sync workers |
| **Docs** | http://localhost:4000 | Documentation site |

Open http://localhost:3001, create your account, and connect your first data source.

## Step 6: Your first search

1. Sign in at http://localhost:3001
2. Go to **Settings > Connectors**
3. Connect a source (Slack, Gmail, or Notion are fastest to set up)
4. Wait for the initial sync to complete (watch progress on the connector page)
5. Search across your connected data from the home page

## Useful commands

| Command | Purpose |
|---------|---------|
| `bun run dev` | Start all apps (web, server, worker, docs) |
| `bun run dev:web` | Start web frontend only |
| `bun run dev:server` | Start API server only |
| `bun run check` | Lint and format with Biome |
| `bun run build` | Build all packages and apps |
| `bun run db:push` | Push Prisma schema to database |
| `bun run db:studio` | Open Prisma Studio (database GUI) |
| `bun run db:migrate` | Run database migrations |
| `bun test` | Run all tests |

## Start individual services

If you only need to work on a specific part:

```bash
# Frontend only (requires server to be running)
bun run dev:web

# Server only
bun run dev:server

# Python ML engine (requires uv)
cd apps/engine && uv sync && uv run python -m src.engine.main
```

    ```bash title=".env"
    GITHUB_CLIENT_SECRET=...

    GCS_ACCESS_KEY_ID=openplane-minio
    GCS_SECRET_ACCESS_KEY=minioadmin
    GCS_BUCKET=openplane-files
    GCS_REGION=us-east-1
    ```
  </Accordion>
  <Accordion title="Infrastructure ports">
    These are the internal infrastructure ports from the Docker Compose setup:

    | Service | Port | Notes |
    |---------|------|-------|
    | PostgreSQL | `5432` | Default postgres credentials |
    | Redis | `6379` | No auth in development |
    | Vespa | `8280` (feed), `19071` (config) | Takes ~2 min to start |
    | Temporal | `7233` | Workflow engine |
    | Temporal UI | `8233` | Workflow dashboard |
    | MinIO | `9000` (API), `9001` (console) | S3-compatible storage |
    | Grafana | `3002` | Monitoring dashboards |
    | Prometheus | `9090` | Metrics collection |
  </Accordion>
</Accordions>

## Troubleshooting

<Accordions>
  <Accordion title="Vespa fails to start or stays unhealthy">
    Vespa requires at least 4 GB of memory allocated to Docker. Check your Docker Desktop settings and increase memory if needed. On first start, Vespa can take up to 3 minutes. Check logs with:

    ```bash
    docker logs openplane-vespa
    ```
  </Accordion>
  <Accordion title="Database connection refused">
    Ensure PostgreSQL is running and healthy:

    ```bash
    docker compose -f scripts/deploy/infra-hetzner-compose.yaml ps postgres
    ```

    The `DATABASE_URL` in your `.env` must match the credentials in the compose file. Default is `postgresql://postgres:postgres@localhost:5432/openplane`.
  </Accordion>
  <Accordion title="Temporal worker fails to connect">
    The Temporal server needs to be fully initialized before workers can connect. Check that the Temporal container is healthy:

    ```bash
    docker compose -f scripts/deploy/infra-hetzner-compose.yaml ps temporal
    ```

    Temporal depends on PostgreSQL, so if Postgres is unhealthy, Temporal will not start.
  </Accordion>
  <Accordion title="bun install fails or is slow">
    Make sure you are using Bun 1.3.2 or later. Check with `bun --version`. If you have a stale lockfile, remove `node_modules` and `bun.lock`, then reinstall:

    ```bash
    rm -rf node_modules bun.lock
    bun install
    ```
  </Accordion>
</Accordions>
