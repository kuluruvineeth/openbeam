# CLI

The `openbeam` CLI is a statically-compiled Go binary that wraps the entire OpenBeam API. Search your indexed content, trigger syncs, run AI agents, manage connectors, and serve an MCP endpoint for AI tool integration — all without leaving the terminal.

Built with Cobra, Go 1.24, zero CGO dependencies. Ships as a single binary for every major platform.

## Quick Start

From zero to first search result in three commands:

```bash
# 1. Store your API key
openbeam auth login --api-key "op_your_api_key_here"

# 2. Search across all connected sources
openbeam search query --query "quarterly revenue report"

# 3. Ask the AI assistant
openbeam rag ask --query "Summarize our Q4 OKR progress"
```

## Authentication

The CLI resolves credentials through a three-tier chain. The first source that returns a value wins.

| Priority | Source | Details |
|----------|--------|---------|
| 1 | Environment variable | `OPENBEAM_API_KEY` |
| 2 | OS keyring | macOS Keychain, GNOME Keyring, Windows Credential Manager |
| 3 | File store | `~/.config/openbeam/secrets.yaml` (permissions `0600`) |

### Storing credentials

```bash
# Store and verify against the server
openbeam auth login --api-key "op_your_key"

# Store without server verification
openbeam auth login --api-key "op_your_key" --skip-verify

# Check current auth status
openbeam auth status

# Verify the stored key is still valid
openbeam auth status --verify

# Remove stored credentials
openbeam auth logout
```

### Environment variable override

For CI/CD or scripting, set the environment variable directly. It takes precedence over all other sources.

```bash
export OPENBEAM_API_KEY="op_your_key"
openbeam search query --query "deployment checklist"
```

## Profiles

Profiles let you maintain separate configurations for different environments (production, staging, local development). Config lives at `~/.config/openbeam/config.yaml`.

```yaml
current_profile: default
profiles:
  default:
    host: http://localhost:3000
    team: ""
    output: ""
    color: auto
    timeout: 30s
    api_key_ref: default
  production:
    host: https://openbeam.example.com
    team: "team_abc123"
    color: auto
    timeout: 30s
    api_key_ref: production
```

### Managing profiles

```bash
# Show active profile
openbeam config show

# List all profiles
openbeam config profiles

# Switch active profile
openbeam config use production

# Set a value on the active profile
openbeam config set --host https://openbeam.example.com
openbeam config set --team "team_abc123"
openbeam config set --timeout 60s
```

### Resolution chain

Every setting follows the same precedence: CLI flag, then environment variable, then profile value, then default.

| Setting | Flag | Env Var | Default |
|---------|------|---------|---------|
| API host | `--host` | `OPENBEAM_HOST` | `http://localhost:3000` |
| Team | `--team` | `OPENBEAM_TEAM` | (none) |
| API Key | -- | `OPENBEAM_API_KEY` | keyring/file store |
| Output format | `--output` | -- | `table` (TTY) / `json` (pipe) |
| Color | `--color` | `NO_COLOR` | `auto` |
| Timeout | `--timeout` | -- | `30s` |

## Output Formats

The CLI auto-detects your context. Interactive terminal gets human-readable tables. Piped output defaults to JSON for machine consumption.

| Format | Flag | When to Use |
|--------|------|-------------|
| `table` | `--output table` | Interactive use (default in TTY) |
| `json` | `--output json` | Scripts, jq piping (default when piped) |
| `yaml` | `--output yaml` | Config files, readability |
| `ndjson` | `--output ndjson` | Streaming, log aggregation |

### Post-processing

Transform output inline without external tools.

```bash
# JQ expression — filter and reshape JSON
openbeam search query --query "roadmap" --jq '.items[].title'

# Go template — format individual fields
openbeam connectors list --template '{{.name}} ({{.type}})'

# Raw — emit the unprocessed response body
openbeam search query --query "test" --raw
```

### Piping examples

```bash
# Count search results
openbeam search query --query "onboarding" --jq '.items | length'

# Extract connector IDs for scripting
openbeam connectors list --jq '.items[].id' | while read id; do
  openbeam connectors status --id "$id"
done

# Export to file
openbeam search query --query "architecture" --output json > results.json
```

## MCP Server

The CLI includes a built-in Model Context Protocol server for AI tool integration. It bridges JSON-RPC 2.0 over stdin/stdout to the OpenBeam HTTP API.

```bash
openbeam mcp serve
```

This exposes all OpenBeam capabilities as MCP tools, resources, and prompts. AI editors and agents can use the full search, RAG, and connector APIs through the standard MCP protocol.

Supported JSON-RPC methods:

| Method | Description |
|--------|-------------|
| `initialize` | Server handshake |
| `tools/list` | List available tools |
| `tools/call` | Execute a tool |
| `resources/list` | List resources |
| `resources/read` | Read a resource |
| `prompts/list` | List prompts |
| `prompts/get` | Retrieve a prompt |

## Plugin System

Extend the CLI with external binaries. Any executable named `openbeam-{name}` discovered on your PATH becomes a subcommand.

```bash
# List discovered plugins
openbeam plugin list

# Install a plugin from a local binary
openbeam plugin install --name my-tool --source ./my-tool-binary

# Run a plugin directly
openbeam my-tool [args...]
```

### Discovery order

1. `$XDG_CONFIG_HOME/openbeam/plugins/`
2. Directories in `OPENBEAM_PLUGIN_PATH`
3. System `$PATH`

Plugins receive stdin, stdout, and stderr forwarded from the parent process. Unknown commands are automatically dispatched to matching plugins.

## Daemon

The CLI can manage a local headless daemon for agent orchestration, speech processing, and worktree management.

```bash
# Start the daemon
openbeam daemon start

# Check daemon status
openbeam daemon status

# Stop the daemon
openbeam daemon stop

# Pair with a remote instance
openbeam daemon pair --host https://openbeam.example.com
```

## Exit Codes

Every exit code has a specific meaning for scripting and automation.

| Code | Meaning | Example |
|------|---------|---------|
| `0` | Success | Command completed |
| `1` | Unknown error | Unclassified failure |
| `2` | Usage error | Invalid flags, bad input |
| `3` | Auth error | Missing or expired API key |
| `4` | Forbidden | Insufficient permissions |
| `5` | Not found | Resource does not exist |
| `6` | Conflict | Resource already exists |
| `7` | Rate limited | Too many requests |
| `9` | Timeout | Request exceeded deadline |
| `10` | Network error | Cannot reach server |
| `11` | Server error | 5xx from API |

## HTTP Client Details

Every request includes these headers automatically.

| Header | Value |
|--------|-------|
| `Authorization` | `Bearer {api_key}` |
| `X-Request-ID` | `opcli-{random}-{sequence}` |
| `X-Openbeam-Team` | Team identifier (when set) |
| `User-Agent` | `openbeam-cli/0.1.0` |
| `Accept` | `application/json` |
| `Content-Type` | `application/json` (when body present) |
