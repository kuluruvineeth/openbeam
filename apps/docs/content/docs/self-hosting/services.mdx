# Infrastructure Services

All infrastructure services are defined in `scripts/deploy/infra-hetzner-compose.yaml`. They communicate over the `openplane` Docker network and bind ports to `127.0.0.1` only -- never exposed directly to the internet.

---

## PostgreSQL

Primary relational database. Stores users, teams, connectors, OAuth tokens, sync history, and all application state.

### Configuration

| Setting | Value | Notes |
|---------|-------|-------|
| Image | `postgres:16-alpine` | |
| Port | `5432` (localhost only) | |
| Memory limit | 2 GB | |
| CPU limit | 1.0 | |
| Data volume | `/mnt/openplane-data/postgres` | |

### Tuning Parameters

The compose file passes these tuning flags optimized for a dedicated 2 GB instance:

| Parameter | Value | Purpose |
|-----------|-------|---------|
| `shared_buffers` | 512 MB | Shared memory for caching (25% of RAM) |
| `effective_cache_size` | 1536 MB | Planner hint for OS cache (75% of RAM) |
| `maintenance_work_mem` | 128 MB | Memory for VACUUM, CREATE INDEX |
| `work_mem` | 8 MB | Per-sort/hash memory |
| `max_connections` | 100 | Connection pool ceiling |
| `wal_buffers` | 16 MB | WAL write buffer |
| `checkpoint_completion_target` | 0.9 | Spread checkpoint writes |
| `random_page_cost` | 1.1 | Tuned for SSD |
| `effective_io_concurrency` | 200 | Tuned for SSD |
| `max_wal_size` | 1 GB | WAL size before checkpoint |
| `min_wal_size` | 80 MB | Minimum WAL retention |
| `log_min_duration_statement` | 1000 | Log queries > 1 second |

### Health Check

```bash
pg_isready -U postgres
```

Interval: 10s, timeout: 5s, retries: 5.

### Scaling Notes

For larger deployments (500+ users, millions of documents):

- Increase `shared_buffers` to 25% of total server RAM
- Increase `max_connections` if you run multiple worker instances
- Consider connection pooling with PgBouncer
- Enable `pg_stat_statements` for query performance analysis
- Set up streaming replication for read replicas

### Troubleshooting

<Accordions>
  <Accordion title="Connection refused">
    Check if PostgreSQL has finished starting: `docker logs postgres`. The `postgres-auth-fix` init container must complete before Temporal can connect. Verify with `docker compose -f scripts/deploy/infra-hetzner-compose.yaml ps`.
  </Accordion>
  <Accordion title="Slow queries">
    Queries taking longer than 1 second are logged automatically. Check with `docker logs postgres 2>&1 | grep duration`. Consider adding indexes or increasing `work_mem` for complex aggregations.
  </Accordion>
  <Accordion title="Disk space">
    Monitor with `docker exec postgres df -h /var/lib/postgresql/data`. Run `VACUUM ANALYZE` to reclaim space from deleted rows.
  </Accordion>
</Accordions>

## Redis

In-memory data store used for caching, rate limiting, job queues, and pub/sub messaging.

### Configuration

| Setting | Value | Notes |
|---------|-------|-------|
| Image | `redis:8.4.0-alpine` | |
| Port | `6379` (localhost only) | |
| Memory limit | 512 MB | |
| CPU limit | 0.5 | |
| Data volume | `/mnt/openplane-data/redis` | |
| Persistence | AOF (`appendonly yes`) | |
| Max memory | 512 MB | |
| Eviction policy | `noeviction` | Errors on OOM instead of dropping keys |

### Health Check

```bash
redis-cli ping
```

Interval: 10s, timeout: 3s, retries: 5.

### Why noeviction

The `noeviction` policy is intentional. OpenPlane uses Redis for rate limiting counters and job state that must not be silently dropped. If Redis runs out of memory, the application surfaces an error rather than silently losing data.

### Monitoring

A Redis exporter (`oliver006/redis_exporter:v1.58.0-alpine`) is included in the compose file. It exposes metrics at `localhost:9121` for Prometheus scraping, including:

- Memory usage
- Connected clients
- Key counts (filtered to `ratelimit:*` and `jobSchedulerKeys:*`)
- Command statistics

### Troubleshooting

<Accordions>
  <Accordion title="OOM errors">
    If you see `OOM command not allowed`, Redis has hit the 512 MB limit. Check key counts with `docker exec openplane-redis redis-cli info keyspace`. Consider increasing `--maxmemory` or debugging key growth.
  </Accordion>
  <Accordion title="High latency">
    Run `docker exec openplane-redis redis-cli --latency` to measure baseline latency. Check if AOF rewriting is causing I/O contention with `docker exec openplane-redis redis-cli info persistence`.
  </Accordion>
</Accordions>

## Vespa

Hybrid search engine combining BM25 text search with vector similarity search. Vespa is the most resource-intensive infrastructure service.

### Configuration

| Setting | Value | Notes |
|---------|-------|-------|
| Image | `vespaengine/vespa:8` | |
| Ports | `8080` (query), `19071` (config) | Mapped to `8280` and `19071` on localhost |
| Memory limit | 4 GB | |
| Memory reservation | 4 GB | Guaranteed allocation |
| CPU limit | 2.0 | |
| Data volume | `/mnt/openplane-data/vespa` | |

### Health Check

```bash
curl -f http://localhost:19071/state/v1/health
```

Interval: 30s, timeout: 10s, start period: 120s, retries: 5.

The 120-second start period accounts for Vespa's JVM initialization time. Vespa is not ready to serve queries until the config server and content nodes are fully bootstrapped.

### Application Deployment

The `vespa-deploy` init container automatically deploys the Vespa application package after the service is healthy:

1. Waits for Vespa to be healthy
2. Zips the application package from `/mnt/openplane-data/configs/vespa-application`
3. Deploys it to the config server at port 19071

### Monitoring

A JSON exporter (`quay.io/prometheuscommunity/json-exporter`) scrapes Vespa metrics and exposes them as Prometheus metrics at `localhost:9116`.

### Scaling Notes

Vespa benefits more from memory and disk speed than CPU:

- 4 GB is the minimum for production. 8+ GB recommended for large document sets.
- Use NVMe SSDs for the data volume. Vespa memory-maps files and depends on fast page cache fills.
- For horizontal scaling, Vespa supports multi-node clusters. See the [Vespa documentation](https://docs.vespa.ai/) for cluster configuration.

### Troubleshooting

<Accordions>
  <Accordion title="Vespa not starting">
    Vespa requires 4 GB of memory. If the container is killed by the OOM killer, increase Docker's memory limit. Check with `docker inspect openplane-vespa | grep -i oom`.
  </Accordion>
  <Accordion title="Slow search queries">
    Check Vespa metrics at `http://localhost:8280/state/v1/metrics`. High `content.proton.documentdb.matching.query_latency` indicates insufficient memory for query caching.
  </Accordion>
  <Accordion title="Deployment fails">
    Check the deploy init container logs: `docker logs openplane-vespa-deploy`. Common issues include malformed schema files or version incompatibilities.
  </Accordion>
  <Accordion title="Disk full">
    Vespa stops accepting writes at 90% disk usage (`VESPA_DISK_FULL_PERCENT`). Free disk space or expand the volume.
  </Accordion>
</Accordions>

## Temporal

Workflow orchestration engine. Manages connector sync schedules, retry logic, and long-running background tasks.

### Configuration

| Setting | Value | Notes |
|---------|-------|-------|
| Image | `temporalio/auto-setup:1.29.2` | Auto-creates schemas on first start |
| Port | `7233` (localhost only) | gRPC endpoint |
| Memory limit | 1 GB | |
| CPU limit | 1.0 | |
| Backend | PostgreSQL | Shares the same PostgreSQL instance |

### Dependencies

Temporal requires PostgreSQL with the correct auth configuration. The `postgres-auth-fix` init container ensures MD5 password hashing is set before Temporal starts.

Startup order: PostgreSQL -> postgres-auth-fix -> Temporal.

### Health Check

```bash
temporal operator cluster health --address localhost:7233
```

Interval: 30s, timeout: 10s, start period: 180s, retries: 10.

The 180-second start period accounts for schema creation on first boot. Subsequent restarts are faster.

### Temporal UI

The Temporal UI (`temporalio/ui:2.44.1`) provides a web dashboard at `localhost:8233` for inspecting workflows, activities, and schedules. It connects to Temporal via `temporal:7233`.

### Admin Tools

A Temporal admin tools container (`temporalio/admin-tools:1.29`) is available for debugging. Access it with:

```bash
docker exec -it openplane-temporal-admin tctl namespace list
docker exec -it openplane-temporal-admin tctl workflow list
```

### Troubleshooting

<Accordions>
  <Accordion title="Temporal cannot connect to PostgreSQL">
    Verify PostgreSQL is healthy and the `postgres-auth-fix` container completed successfully: `docker logs postgres-auth-fix`. Temporal requires MD5 password encryption, which the init container configures.
  </Accordion>
  <Accordion title="Workflows stuck in running state">
    Check the Temporal UI at `http://localhost:8233`. A workflow stuck in running state usually means the worker process crashed. Check worker logs: `docker logs openplane-worker`.
  </Accordion>
  <Accordion title="Schema creation failed">
    On first start, `auto-setup` creates Temporal tables in PostgreSQL. If this fails, check `docker logs openplane-temporal`. Common cause: PostgreSQL not ready yet. Restart the Temporal container.
  </Accordion>
</Accordions>

## MinIO

S3-compatible object storage for file uploads, document attachments, and media files.

### Configuration

| Setting | Value | Notes |
|---------|-------|-------|
| Image | `minio/minio:latest` | |
| Ports | `9000` (API), `9001` (console) | Localhost only |
| Memory limit | 512 MB | |
| CPU limit | 0.5 | |
| Data volume | `/mnt/openplane-data/minio` | |

### Initialization

The `minio-init` container runs on first start to:

1. Set up the MinIO CLI alias
2. Create the default bucket (`openplane-files`)
3. Configure CORS for browser-based uploads

### Health Check

```bash
mc ready local
```

Interval: 10s, timeout: 5s, retries: 5.

### Console Access

The MinIO console is available at `http://localhost:9001`. Login with `MINIO_ROOT_USER` and `MINIO_ROOT_PASSWORD`.

### Using External S3

To use AWS S3 or another S3-compatible service instead of MinIO:

1. Remove the `minio` and `minio-init` services from the compose file
2. Set `GCS_ENDPOINT` to your S3 endpoint (e.g., `https://s3.amazonaws.com`)
3. Set `GCS_ACCESS_KEY_ID` and `GCS_SECRET_ACCESS_KEY` to your IAM credentials
4. Set `GCS_BUCKET` to your bucket name
5. Set `GCS_REGION` to your bucket's region

### Troubleshooting

<Accordions>
  <Accordion title="Upload failures">
    Check CORS configuration. The `minio-init` container sets `cors_allow_origin="*"`. If you restricted this, ensure your web frontend's origin is included. After changing CORS, restart the MinIO container.
  </Accordion>
  <Accordion title="Bucket not found">
    The `minio-init` container creates the bucket on first start. If it failed, run it manually: `docker exec openplane-minio mc mb myminio/openplane-files --ignore-existing`.
  </Accordion>
</Accordions>

## Monitoring Stack

The monitoring stack is optional but recommended for production deployments.

### Prometheus

Scrapes metrics from all services on a 15-30 second interval. Retains data for 30 days.

| Setting | Value |
|---------|-------|
| Image | `prom/prometheus:latest` |
| Port | `9090` (localhost only) |
| Memory limit | 512 MB |
| Retention | 30 days |
| Config | `/mnt/openplane-data/configs/prometheus/prometheus.yml` |

Health check: `http://localhost:9090/-/healthy`

### Grafana

Dashboards and alerting. Pre-provisioned with data sources and dashboards.

| Setting | Value |
|---------|-------|
| Image | `grafana/grafana:latest` |
| Port | `3002` (localhost only) |
| Memory limit | 256 MB |
| Data volume | `/mnt/openplane-data/grafana` |
| Default credentials | `admin` / `admin` (change in `.env`) |

Health check: `http://localhost:3000/api/health` (internal port 3000, mapped to 3002)

### Loki

Log aggregation backend. Collects logs from all containers via Promtail.

| Setting | Value |
|---------|-------|
| Image | `grafana/loki:2.9.10` |
| Port | `3100` (localhost only) |
| Memory limit | 256 MB |
| Data volume | `/mnt/openplane-data/loki` |

### Promtail

Log shipping agent. Reads Docker container logs and forwards them to Loki.

| Setting | Value |
|---------|-------|
| Image | `grafana/promtail:2.9.10` |
| Memory limit | 128 MB |
| Mounts | Docker socket (read-only), container logs (read-only) |

## Network Architecture

```text
                                Internet
                                   |
                          [ Reverse Proxy ]
                          (Caddy / Nginx)
                           /            \
                    :3001 /              \ :3000
                         /                \
              ┌─────────┐                  ┌─────────┐
              │   Web   │                  │ Server  │
              └────┬────┘                  └────┬────┘
                   │      openplane-apps        │
              ─────┼────────────────────────────┼─────
                   │       openplane            │
          ┌────────┼────────────────────────────┼────────┐
          │        │                            │        │
     ┌────┴───┐ ┌──┴──┐ ┌──────┐ ┌────────┐ ┌──┴──┐    │
     │Worker  │ │Redis│ │Vespa │ │Temporal│ │MinIO│    │
     └────────┘ └─────┘ └──────┘ └────────┘ └─────┘    │
          │        │        │         │         │        │
          │   ┌────┴────┐   │    ┌────┴────┐    │        │
          │   │Postgres │   │    │Temporal │    │        │
          │   │         │   │    │  UI     │    │        │
          │   └─────────┘   │    └─────────┘    │        │
          └──────────────────────────────────────┘
```

All infrastructure services communicate via Docker DNS names (e.g., `postgres`, `redis`, `vespa`). No IP addresses are hardcoded.
