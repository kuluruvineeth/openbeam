# Self-Hosting

OpenBeam is MIT-licensed and designed to run on your infrastructure. Your data never leaves your network. No phone-home telemetry, no feature gates.

## Why Self-Host

| Reason | Details |
|--------|---------|
| **Data sovereignty** | All indexed content, embeddings, and AI interactions stay on your servers |
| **Compliance** | Meet SOC 2, HIPAA, GDPR requirements without third-party data processing |
| **Customization** | Modify, extend, and integrate with internal systems |
| **Cost control** | No per-seat pricing. Scale on your own hardware |
| **Air-gapped environments** | Deploy in networks with no internet access |

## Architecture

OpenBeam consists of 4 application services and 5 infrastructure services.

### Application Services

| Service | Image | Port | Memory | CPUs | Purpose |
|---------|-------|------|--------|------|---------|
| **Server** | `openbeam-server` | 3000 | 1 GB | 1.0 | Hono API server, OAuth, webhooks |
| **Web** | `openbeam-web` | 3001 | 1 GB | 1.0 | Next.js frontend |
| **Worker** | `openbeam-worker` | 9092 (health) | 2 GB | 2.0 | Temporal workflows, sync jobs |
| **Engine** | `openbeam-engine` | 8000 | 2 GB | 2.0 | Python ML service, embeddings |

### Infrastructure Services

| Service | Image | Port | Memory | CPUs | Purpose |
|---------|-------|------|--------|------|---------|
| **PostgreSQL** | `postgres:16-alpine` | 5432 | 2 GB | 1.0 | Primary database |
| **Redis** | `redis:8.4.0-alpine` | 6379 | 512 MB | 0.5 | Cache, queues, rate limiting |
| **Vespa** | `vespaengine/vespa:8` | 8080, 19071 | 4 GB | 2.0 | Search engine (hybrid BM25 + vector) |
| **Temporal** | `temporalio/auto-setup:1.29.2` | 7233 | 1 GB | 1.0 | Workflow orchestration |
| **MinIO** | `minio/minio` | 9000, 9001 | 512 MB | 0.5 | S3-compatible object storage |

### Monitoring Stack (optional)

| Service | Purpose |
|---------|---------|
| Prometheus | Metrics collection |
| Grafana | Dashboards and alerting |
| Loki + Promtail | Log aggregation |
| Redis Exporter | Redis metrics |
| Vespa Exporter | Search metrics |

## Hardware Requirements

### Minimum (small team, < 50 users)

| Resource | Specification |
|----------|---------------|
| CPU | 4 cores |
| RAM | 16 GB |
| Disk | 100 GB SSD |
| OS | Linux (Ubuntu 22.04+ recommended) |

### Recommended (medium team, 50-500 users)

| Resource | Specification |
|----------|---------------|
| CPU | 8 cores |
| RAM | 32 GB |
| Disk | 500 GB NVMe SSD |
| OS | Linux (Ubuntu 22.04+ recommended) |

These estimates are derived from the Docker Compose resource limits: PostgreSQL (2 GB), Vespa (4 GB), Worker (2 GB), Engine (2 GB), and the remaining services sharing the rest. Vespa is the most memory-intensive service and benefits from fast disk I/O.

## Quick Start

Get a full deployment running in under 10 minutes.

```bash
# 1. Clone the repository
git clone https://github.com/kuluruvineeth/openbeam.git
cd openbeam

# 2. Create your environment file from the template
cp apps/server/.env.example .env
# Edit .env with your secrets (see Configuration page for all variables)

# 3. Create the data directory
sudo mkdir -p /mnt/openbeam-data

# 4. Start infrastructure services
docker compose -f scripts/deploy/infra-hetzner-compose.yaml up -d

# 5. Wait for infrastructure to be healthy (~2-3 minutes)
docker compose -f scripts/deploy/infra-hetzner-compose.yaml ps

# 6. Start application services
docker compose -f scripts/deploy/apps-compose.yaml up -d

# 7. Verify everything is running
docker compose -f scripts/deploy/apps-compose.yaml ps
```

Open `http://your-server:3001` to access the web interface.

## Network Architecture

The deployment uses two Docker networks:

| Network | Purpose | Services |
|---------|---------|----------|
| `openbeam` | Infrastructure services | PostgreSQL, Redis, Vespa, Temporal, MinIO |
| `openbeam-apps` | Application services | Server, Web, Worker, Engine |

Application services join both networks so they can reach infrastructure via Docker DNS (e.g., `redis:6379`, `vespa:8080`). All infrastructure ports are bound to `127.0.0.1` only -- they are not exposed to the public internet.
