# Docker Compose Deployment

OpenBeam uses two compose files that form a complete deployment:

| File | Purpose | Services |
|------|---------|----------|
| `scripts/deploy/infra-hetzner-compose.yaml` | Infrastructure layer | PostgreSQL, Redis, Vespa, Temporal, MinIO, monitoring |
| `scripts/deploy/apps-compose.yaml` | Application layer | Server, Web, Worker, Engine |

Infrastructure starts first. Applications depend on infrastructure being healthy before they launch.

## Prerequisites

| Requirement | Version | Notes |
|-------------|---------|-------|
| Docker Engine | 24.0+ | `docker --version` |
| Docker Compose | v2.20+ | `docker compose version` |
| Server | 8+ cores, 32 GB RAM | See [hardware requirements](/docs/self-hosting#hardware-requirements) |
| Domain | Required for HTTPS | Point DNS A record to your server IP |
| Disk | 100+ GB SSD | Mounted at `/mnt/openbeam-data` |

## Step 1: Clone and Configure

```bash
git clone https://github.com/kuluruvineeth/openbeam.git
cd openbeam
```

Create your environment file:

```bash
cp .env.example .env
```

At minimum, set these values in `.env`:

```bash
# Security (REQUIRED - generate unique values)
JWT_SECRET=$(openssl rand -hex 32)
ENCRYPTION_KEY=$(openssl rand -hex 32)

# URLs (REQUIRED - match your domain)
WEB_URL=https://app.example.com
SERVER_URL=https://api.example.com
COOKIE_DOMAIN=.example.com

# Database
DATABASE_URL=postgresql://postgres:postgres@postgres:5432/openbeam

# Auth provider (at least one required)
GOOGLE_CLIENT_ID=your_google_client_id
GOOGLE_CLIENT_SECRET=your_google_client_secret

# Object storage
GCS_ACCESS_KEY_ID=openbeam-minio
GCS_SECRET_ACCESS_KEY=minioadmin
GCS_BUCKET=openbeam-files
GCS_REGION=us-east-1
GCS_PUBLIC_ENDPOINT=https://storage.example.com

# AI (at least one required)
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...
```

See the [Configuration Reference](/docs/self-hosting/configuration) for all available variables.

## Step 2: Prepare Data Directory

Create the data directory and required config subdirectories:

```bash
sudo mkdir -p /mnt/openbeam-data/{postgres,redis,vespa,minio,grafana,prometheus,loki}
sudo mkdir -p /mnt/openbeam-data/configs/{temporal/dynamicconfig,prometheus,grafana/provisioning,grafana/dashboards,promtail,loki,vespa-application}
```

<Callout type="warn">
  The data directory must be on a fast disk (SSD or NVMe). Vespa and PostgreSQL performance depends heavily on disk I/O speed.
</Callout>

### Temporal Dynamic Config

Create a minimal dynamic config file:

```bash
cat > /mnt/openbeam-data/configs/temporal/dynamicconfig/development.yaml << 'EOF'
{}
EOF
```

### Loki Config

```bash
cat > /mnt/openbeam-data/configs/loki/loki-config.yml << 'EOF'
auth_enabled: false
server:
  http_listen_port: 3100
common:
  path_prefix: /loki
  storage:
    filesystem:
      chunks_directory: /loki/chunks
      rules_directory: /loki/rules
  replication_factor: 1
  ring:
    kvstore:
      store: inmemory
schema_config:
  configs:
    - from: 2020-10-24
      store: tsdb
      object_store: filesystem
      schema: v13
      index:
        prefix: index_
        period: 24h
EOF
```

## Step 3: Start Infrastructure

```bash
docker compose -f scripts/deploy/infra-hetzner-compose.yaml up -d
```

Watch the startup progress. Vespa takes the longest (2-3 minutes to become healthy).

```bash
docker compose -f scripts/deploy/infra-hetzner-compose.yaml ps
```

Wait until all services show `healthy` status. The `postgres-auth-fix`, `minio-init`, and `vespa-deploy` containers are one-shot tasks -- they run once and exit.

| Service | Health Check | Expected Startup |
|---------|-------------|-----------------|
| PostgreSQL | `pg_isready` | ~10 seconds |
| Redis | `redis-cli ping` | ~5 seconds |
| Vespa | HTTP `/state/v1/health` | ~2-3 minutes |
| MinIO | `mc ready local` | ~10 seconds |
| Temporal | `temporal operator cluster health` | ~3 minutes (waits for PostgreSQL) |

## Step 4: Start Applications

```bash
docker compose -f scripts/deploy/apps-compose.yaml up -d
```

Applications depend on infrastructure via the shared `openbeam` Docker network. The server starts first, then web and worker launch after the server is healthy.

```bash
# Watch logs during first startup
docker compose -f scripts/deploy/apps-compose.yaml logs -f

# Check health
docker compose -f scripts/deploy/apps-compose.yaml ps
```

## Step 5: Verify Deployment

Run through this checklist to confirm everything is working.

```bash
# API server responds
curl -s http://localhost:3000/ | head -c 100

# Web frontend loads
curl -s -o /dev/null -w "%{http_code}" http://localhost:3001/

# Worker health check
curl -s http://localhost:9092/health

# Engine health check
curl -s http://localhost:8000/v1/health
```

## Reverse Proxy and SSL

<Callout type="info">
  All infrastructure ports bind to 127.0.0.1 by default. Application ports (3000, 3001) are exposed publicly. Use a reverse proxy to add HTTPS.
</Callout>

### Caddy (Recommended)

Caddy handles automatic HTTPS with Let's Encrypt certificates.

```bash
sudo apt install caddy
```

```bash
# /etc/caddy/Caddyfile
app.example.com {
    reverse_proxy localhost:3001
}

api.example.com {
    reverse_proxy localhost:3000
}

storage.example.com {
    reverse_proxy localhost:9000
}
```

```bash
sudo systemctl reload caddy
```

### Nginx Alternative

```nginx
server {
    listen 443 ssl http2;
    server_name app.example.com;

    ssl_certificate /etc/letsencrypt/live/app.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/app.example.com/privkey.pem;

    location / {
        proxy_pass http://localhost:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

server {
    listen 443 ssl http2;
    server_name api.example.com;

    ssl_certificate /etc/letsencrypt/live/api.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/api.example.com/privkey.pem;

    client_max_body_size 100M;

    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## Updating

Pull new images and restart services with zero-downtime rolling updates.

```bash
# Pull latest images
docker compose -f scripts/deploy/apps-compose.yaml pull

# Restart with new images
docker compose -f scripts/deploy/apps-compose.yaml up -d

# Verify health
docker compose -f scripts/deploy/apps-compose.yaml ps
```

For infrastructure updates (major version bumps), stop and restart the infrastructure stack. Back up your data first.

## Backup Strategy

### PostgreSQL

```bash
# Full dump
docker exec postgres pg_dump -U postgres openbeam > backup_$(date +%Y%m%d).sql

# Automated daily backups via cron
0 3 * * * docker exec postgres pg_dump -U postgres openbeam | gzip > /backups/openbeam_$(date +\%Y\%m\%d).sql.gz
```

### Vespa

Vespa stores data in `/mnt/openbeam-data/vespa`. Back up this directory during a maintenance window.

```bash
# Stop vespa, copy data, restart
docker compose -f scripts/deploy/infra-hetzner-compose.yaml stop vespa
rsync -av /mnt/openbeam-data/vespa/ /backups/vespa_$(date +%Y%m%d)/
docker compose -f scripts/deploy/infra-hetzner-compose.yaml start vespa
```

### MinIO

```bash
# Use mc (MinIO Client) for bucket backups
docker exec openbeam-minio mc mirror myminio/openbeam-files /backups/minio/
```

### Redis

Redis uses AOF persistence. The data directory at `/mnt/openbeam-data/redis` can be backed up directly.

## Stopping Everything

```bash
# Stop applications first
docker compose -f scripts/deploy/apps-compose.yaml down

# Stop infrastructure
docker compose -f scripts/deploy/infra-hetzner-compose.yaml down
```

<Callout type="warn">
  Using `down -v` will delete Docker volumes. Data stored in `/mnt/openbeam-data` is not affected since it uses bind mounts.
</Callout>

## Post-Deployment Checklist

- [ ] API server responds at `https://api.example.com`
- [ ] Web frontend loads at `https://app.example.com`
- [ ] Google OAuth login works
- [ ] First connector can be installed and synced
- [ ] Search returns results after sync completes
- [ ] RAG answers reference synced documents
- [ ] Temporal UI accessible at `http://localhost:8233` (internal only)
- [ ] Grafana dashboards loading at `http://localhost:3002` (internal only)
- [ ] SSL certificates are valid and auto-renewing
- [ ] Backup cron jobs are scheduled
