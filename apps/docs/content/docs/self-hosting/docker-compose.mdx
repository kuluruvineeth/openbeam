# Docker Compose Deployment

OpenPlane uses two compose files that form a complete deployment:

| File | Purpose |
|------|---------|
| `scripts/deploy/infra-hetzner-compose.yaml` | Infrastructure: PostgreSQL, Redis, Vespa, Temporal, MinIO, monitoring |
| `scripts/deploy/apps-compose.yaml` | Applications: server, web, worker, engine |

Both stacks communicate over a shared `openplane` Docker network.

## Prerequisites

- Docker Engine 24+ with Compose V2
- 16 GB RAM minimum (see [hardware requirements](/docs/self-hosting#hardware-requirements))
- A data directory with sufficient disk space
- Kernel tuning applied (see below)

```bash
# Verify Docker
docker compose version

# Kernel settings (required for Vespa)
sudo sysctl -w vm.max_map_count=262144
sudo sysctl -w fs.file-max=1048576
```

## Step 1: Clone the Repository

```bash
git clone https://github.com/kuluruvineeth/openplane.git
cd openplane
```

## Step 2: Prepare Data Directories

The infrastructure compose file expects volumes at `/mnt/openplane-data/`. Create the directory structure:

```bash
DATA_DIR="/mnt/openplane-data"
sudo mkdir -p "$DATA_DIR"/{postgres,redis,vespa,minio,prometheus,grafana,loki}

# Set ownership for each service
sudo chown -R 70:70    "$DATA_DIR/postgres"
sudo chown -R 999:999  "$DATA_DIR/redis"
sudo chown -R 1000:1000 "$DATA_DIR/vespa"
sudo chown -R 1000:1000 "$DATA_DIR/minio"
sudo chown -R 65534:65534 "$DATA_DIR/prometheus"
sudo chown -R 472:472  "$DATA_DIR/grafana"
sudo chown -R 10001:10001 "$DATA_DIR/loki"
```

<Callout type="info">
On Hetzner, the `scripts/deploy/bootstrap.sh` script automates this entire setup including volume detection, directory creation, config copying, and kernel tuning. Run it on a fresh server:

```bash
ssh root@<SERVER_IP> 'bash -s' < scripts/deploy/bootstrap.sh
```
</Callout>

## Step 3: Copy Configuration Files

The infrastructure services need config files mounted as volumes:

```bash
DATA_DIR="/mnt/openplane-data"

# Prometheus
mkdir -p "$DATA_DIR/configs/prometheus"
cp monitoring/prometheus/prometheus.yml "$DATA_DIR/configs/prometheus/"
cp monitoring/prometheus/alerts.yml "$DATA_DIR/configs/prometheus/"
cp monitoring/prometheus/recording-rules.yml "$DATA_DIR/configs/prometheus/"
cp monitoring/prometheus/vespa-exporter.yml "$DATA_DIR/configs/prometheus/"

# Grafana
mkdir -p "$DATA_DIR/configs/grafana/provisioning/datasources"
mkdir -p "$DATA_DIR/configs/grafana/provisioning/dashboards"
mkdir -p "$DATA_DIR/configs/grafana/dashboards"
cp monitoring/grafana/provisioning/datasources/datasource.yml "$DATA_DIR/configs/grafana/provisioning/datasources/"
cp monitoring/grafana/provisioning/dashboards/dashboard.yml "$DATA_DIR/configs/grafana/provisioning/dashboards/"
cp monitoring/grafana/dashboards/*.json "$DATA_DIR/configs/grafana/dashboards/" 2>/dev/null

# Loki + Promtail
mkdir -p "$DATA_DIR/configs/loki" "$DATA_DIR/configs/promtail"
cp monitoring/loki/loki-config.yml "$DATA_DIR/configs/loki/"
cp monitoring/promtail/promtail-config.yml "$DATA_DIR/configs/promtail/"

# Temporal
mkdir -p "$DATA_DIR/configs/temporal/dynamicconfig"
cp temporal/dynamicconfig/development.yaml "$DATA_DIR/configs/temporal/dynamicconfig/"

# Vespa application (search schemas)
cp -r packages/vespa/application "$DATA_DIR/configs/vespa-application"
cp packages/vespa/deploy.sh "$DATA_DIR/configs/vespa-application/"
```

## Step 4: Create Environment File

Create a `.env` file in the project root for Docker Compose variable substitution:

```bash title=".env"
# PostgreSQL
POSTGRES_DB=openplane
POSTGRES_USER=postgres
POSTGRES_PASSWORD=CHANGE_ME_STRONG_PASSWORD

# Database URL (used by app services)
DATABASE_URL=postgresql://postgres:CHANGE_ME_STRONG_PASSWORD@postgres:5432/openplane

# MinIO
MINIO_ROOT_USER=openplane-minio
MINIO_ROOT_PASSWORD=CHANGE_ME_MINIO_PASSWORD
S3_BUCKET=openplane-files

# Auth (generate with: openssl rand -hex 32)
JWT_SECRET=CHANGE_ME_64_CHAR_HEX
ENCRYPTION_KEY=CHANGE_ME_64_CHAR_HEX

# URLs
WEB_URL=https://app.yourdomain.com
SERVER_URL=https://api.yourdomain.com
COOKIE_DOMAIN=.yourdomain.com

# Google OAuth
GOOGLE_CLIENT_ID=your-client-id
GOOGLE_CLIENT_SECRET=your-client-secret

# AI Keys (at least one required)
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...

# Storage
GCS_ENDPOINT=http://minio:9000
GCS_ACCESS_KEY_ID=openplane-minio
GCS_SECRET_ACCESS_KEY=CHANGE_ME_MINIO_PASSWORD
GCS_BUCKET=openplane-files
GCS_REGION=us-east-1

# Monitoring (optional)
GRAFANA_USER=admin
GRAFANA_PASSWORD=CHANGE_ME_GRAFANA_PASSWORD
```

Generate secrets:

```bash
openssl rand -hex 32  # Use for JWT_SECRET
openssl rand -hex 32  # Use for ENCRYPTION_KEY
```

## Step 5: Start Infrastructure

```bash
docker compose -f scripts/deploy/infra-hetzner-compose.yaml up -d
```

This starts PostgreSQL, Redis, Vespa, Temporal, MinIO, and the monitoring stack. The startup order is managed by health checks and dependencies:

1. PostgreSQL starts first
2. `postgres-auth-fix` runs a one-time password hash fix
3. Temporal starts after PostgreSQL is healthy
4. Vespa starts independently (takes ~2 minutes for initial startup)
5. `vespa-deploy` deploys the search schema after Vespa is healthy
6. `minio-init` creates the default bucket

Wait for all services to be healthy:

```bash
docker compose -f scripts/deploy/infra-hetzner-compose.yaml ps
```

All core services should show `healthy` status. The init containers (`postgres-auth-fix`, `vespa-deploy`, `minio-init`) will show `exited (0)`.

## Step 6: Start Application Services

```bash
docker compose -f scripts/deploy/apps-compose.yaml up -d
```

The application stack starts:

1. **engine-cpu** -- No app dependencies, starts immediately
2. **server** -- Runs database migrations on startup, then starts the API
3. **worker** -- Connects to Temporal and begins processing workflows
4. **web** -- Starts after the server is healthy

## Step 7: Verify

Check that all services are running:

```bash
# Infrastructure
docker compose -f scripts/deploy/infra-hetzner-compose.yaml ps

# Applications
docker compose -f scripts/deploy/apps-compose.yaml ps
```

Test the health endpoints:

```bash
curl http://localhost:3000/health    # Server
curl http://localhost:3001           # Web
curl http://localhost:9092/health    # Worker
curl http://localhost:8000/v1/health # Engine
```

## Health Checks

Every service includes a Docker health check:

| Service | Endpoint | Interval | Start Period |
|---------|----------|----------|-------------|
| PostgreSQL | `pg_isready` | 10s | -- |
| Redis | `redis-cli ping` | 10s | -- |
| Vespa | `GET /state/v1/health` on :19071 | 30s | 120s |
| Temporal | `temporal operator cluster health` | 30s | 180s |
| MinIO | `mc ready local` | 10s | -- |
| Server | `GET /health` on :3000 | 15s | 30s |
| Web | `GET /` on :3001 | 15s | 30s |
| Worker | `GET /health` on :9092 | 15s | 60s |
| Engine | `GET /v1/health` on :8000 | 15s | 30s |

## Upgrading

Pull new images and restart:

```bash
# Applications
docker compose -f scripts/deploy/apps-compose.yaml pull
docker compose -f scripts/deploy/apps-compose.yaml up -d

# Infrastructure (less frequent)
docker compose -f scripts/deploy/infra-hetzner-compose.yaml pull
docker compose -f scripts/deploy/infra-hetzner-compose.yaml up -d
```

Database migrations run automatically when the server container starts (via `scripts/migrate.sh`). The migration script uses `prisma migrate deploy`, which is safe for production and will never reset data.

## Updating Configs

After changing monitoring configs, Vespa schemas, or Temporal dynamic config:

```bash
# Re-sync configs to the data directory
scripts/deploy/sync-configs.sh <SERVER_IP>

# Restart affected containers
docker restart openplane-prometheus openplane-grafana openplane-loki openplane-promtail
```

## Troubleshooting

<Accordions>
  <Accordion title="Container cannot reach infrastructure services">
    Verify the container is on the `openplane` network:

    ```bash
    docker inspect <container-id> | grep -A 5 Networks
    ```

    Both compose files must share the same network. The infrastructure stack creates the `openplane` network, and the apps stack references it as `external: true`.
  </Accordion>
  <Accordion title="Temporal connection refused">
    Use Docker DNS names, not `localhost`. The worker and server connect to Temporal via `temporal:7233` on the Docker network.

    Check that Temporal is healthy:

    ```bash
    docker logs openplane-temporal --tail 50
    ```

    Temporal takes up to 3 minutes on first startup while it runs schema setup against PostgreSQL.
  </Accordion>
  <Accordion title="Vespa deploy fails">
    Vespa needs ~2 minutes to initialize. The `vespa-deploy` init container waits for health before deploying schemas. Check its logs:

    ```bash
    docker logs openplane-vespa-deploy
    ```

    To manually redeploy Vespa schemas:

    ```bash
    cd packages/vespa
    sh deploy.sh localhost 19071
    ```
  </Accordion>
  <Accordion title="Database authentication fails">
    The infrastructure stack uses md5 password authentication. The `postgres-auth-fix` init container re-hashes the password on startup. If auth fails, verify the `DATABASE_URL` password matches `POSTGRES_PASSWORD` in your `.env` file.
  </Accordion>
  <Accordion title="MinIO bucket not created">
    The `minio-init` container creates the bucket on first startup. If it failed:

    ```bash
    docker logs openplane-minio-init
    ```

    To manually create it:

    ```bash
    docker run --rm --network openplane minio/mc \
      alias set myminio http://minio:9000 $MINIO_ROOT_USER $MINIO_ROOT_PASSWORD && \
      mc mb --ignore-existing myminio/openplane-files
    ```
  </Accordion>
</Accordions>
