# Computer

OpenBeam Computer is an autonomous agent platform. Describe what you need in plain language — Computer generates an agent, runs it on schedule, accumulates memory across runs, and waits for your approval before acting on anything sensitive.

## What you get

| Capability | Detail |
|------------|--------|
| Pre-built agents | 6 production-grade agents for knowledge, compliance, and quality |
| Natural language generation | Describe an agent in English — Computer writes the code |
| Durable execution | Temporal-backed workflows survive crashes and restarts |
| Approval workflows | Agents propose destructive actions; you approve individually |
| Persistent memory | Agents remember context across runs — trends, baselines, known issues |
| Secure sandbox | V8 isolation, no filesystem or network access, 64MB / 30s limits |
| Full audit trail | Every tool call, every LLM generation, every decision — logged |
| 5 surfaces | Dashboard, Chat, CLI, REST API, MCP |

## Safety model

Every agent runs inside a `secure-exec` V8 sandbox:

- No filesystem access
- No network access outside declared MCP tools
- 64MB memory limit
- 30-second CPU timeout
- All tool calls go through the team-scoped MCP server

Agents that propose destructive actions (archiving documents, restricting access, sending notifications) pause in `WAITING_APPROVAL` state. You review the proposed actions in the dashboard, CLI, or chat — approve individually with partial selection, or reject the batch. Temporal's durable signals mean the workflow resumes exactly where it paused, with no lost state.

## Execution modes

| Mode | Behavior |
|------|----------|
| `AUTONOMOUS` | Agent executes actions without approval |
| `APPROVAL` | Agent proposes actions and waits for approval |
| `REPORT_ONLY` | Agent reports findings but takes no action |

Set mode per agent in the dashboard Settings tab or via the `updateAgent` API.
